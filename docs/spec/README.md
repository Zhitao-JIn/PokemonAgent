## 二、与其它文档的分工

| 文件 | 是什么 | 会不会跟着代码改 |
|---|---|---|
| `AGENTS.md` | **硬约束**：铁律、风格、目录、测试要求。写代码前先读 | 改规范要先讨论 |
| `CHANGELOG.md` | **决策史**：每次改动四段式留痕（改了什么 / 为什么 / 取舍 / 影响面） | 只追加，**不改写历史条目** |

| `docs/experiments/**` | **实验记录**：每批真机数据的分析 | 不改写 |

## 三、写这些文档的规矩

1. **只描述现在。** "以前是什么、为什么搬过家"进 `CHANGELOG.md`，
   本目录不留历史叙事。**唯一的例外**是本文件与各 SPEC 末尾的"已删且不再回来的东西"
   清单——那是给下一个人省一轮踩坑用的，写清"现在没有它"即可。
2. **每个路径、每个符号都必须真实存在。** 反引号里的 `foo/bar.py`、`Class.method`
   写之前先 grep 一遍。指着一个不存在的文件说"详见"，比不写更糟。
3. **发现代码与文档不一致时**：以代码为准改文档；如果错的是**代码里的 docstring**，
   就改 docstring；如果两边都对但 `AGENTS.md` 说错了，回来改 `AGENTS.md`。
4. **数出来的数字要写口径。** "共 N 处引用"这种话必须说明"一条 `import` 算一处"
   还是"按符号个数拆开"——否则下次复核必然对不上。
5. **能跑的就写怎么跑。** `scripts/check_*_self_contained.py` 这类脚本比散文可靠，
   索引式登记（如 world 的引用面）请以脚本输出为准。
6. 行尾 **LF**、UTF-8，与仓库其它 `.md` 一致。
