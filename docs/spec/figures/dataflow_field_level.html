1 · 总览：模块分层与三条通道

两级 LangGraph 各管一层：run 是完整一局游戏、维护目标栈；episode 只解决栈顶一个目标。三条通道把它们与外围连起来。

2 · run 级：五节点与 RunState 字段

run 级只维护目标栈——弹栈 / 压栈 / 重压都在这里发生，episode 不碰。attempts 与 goals 必须平行增减。

3 · episode 主循环前半：看 / 判 / 五路检索 / 合并

judge 是整张图上唯一的终止裁决节点；五个 retrieve_* 互不依赖，只在 enrich_observation 合流。

4 · episode 主循环后半：决策 / 执行 / 落库 / 收尾链

act 是唯一推进世界的节点；before / rationale / action / after 四件套被三个节点各读一次（停摆检测、写 step 记忆、写 object 事件）。

5 · 通道② trace：信封字段与 payload 词表

信封 · TraceEvent（schema_version = 4）

一条事件一个 trace_data/<run_id>/events/<uuid>.json；TraceTool.append() 是 harness 唯一的记账口。

event_id : int全局单调递增，排序与断线补发的唯一依据
run_id : str哪一次实验，manifest 的 join key
episode_id : str所属局；run 级事件放 run_id
step : int第几步，不是主键（一步内多条）
type : EventType7 类之一，与 source 正交
phase : str循环阶段（observe / retrieve_memory / think / act…），由 type 推导
source : Source8 成员，成本拆分与失败归因按它切
payload : dict[str,str]该类型的结构化内容，纯文本（二进制另开字段）
frame_png : str | None仅 view 类非空，base64 PNG
ts : floatUnix 秒，算延迟用；不能替代 event_id 排序
valid : boolcheckpoint resume 把废弃分支原地打 false，读端一律过滤

run 级读取：读取即过滤

RUN_TRACE_MASK = frozenset({LIFECYCLE, ERROR})
plan 只读这两类（再按 payload.kind 挑 episode_start/end 与 error）。不读 view（帧详情）· model_call（账）· llm_outcome(intent) · act(executed) · memory_io 其余读写。
无 trace_cursor——run 级每次决策都读完整历史，过滤后每局只剩约 5 条高层事件。

6 · 通道③ memory：四类记录、落盘与检索链路

四类记录 · 每条记录一个 uuid 文件（MemoryStore 实例 = 一个 kind = 一个子目录）

StepMemory
step_memory · .json		before · after : Observation 快照 ｜ rationale : list[str] ｜ action : str ｜ step : int ｜ episode_id · run_id ｜ before_frame · after_frame : base64|None
EpisodeMemory
episode_memory · .md		episode_id · run_id · goal · success · steps ｜ summary · reusable_patterns[] · critical_decisions[] · failure_points[] ｜ quality_score · quality_rationale ｜ applicable_scenes[] · tags[] ｜ filename · markdown
ObjectFactEvent
object_memory · .json		episode_id · step · run_id ｜ actor_place{map_id,x,y} · place{map_id,x,y} ｜ kind · button ｜ type ∈ dialog{text} / warp{map_id} / still
knowledge
knowledge_memory · .md		运营手写的领域先验，不挂坐标、不进 trace；查询返回 contents[] + sources[]

落盘布局

memory/<kind>/           kind ∈ step_memory | object_memory | episode_memory | knowledge_memory
├── <uuid>.json         json 类记录（step / object）：整文件 JSON
├── <uuid>.md           md 类记录（episode / knowledge）：JSON frontmatter + 正文
├── index.json          本文件夹倒排索引（派生物，写穿；对账失败就全量重建）
└── vectors.jsonl       语义检索向量缓存 sidecar（惰性加载）
memory/voided-<ts>/<kind>/    checkpoint 恢复时归档的废弃记录（搬走不删除）

检索管线 · memory/retrieval.py（纯函数，只认字符串，不认记忆类型）

documents ─┬─→ BM25Okapi(tokenize＝中文 bigram) ──→ ranking A
           │
           └─→ EmbeddingProvider.embed + 余弦 ──→ ranking B
                        ↓
        RRF 融合（只取排名，避开 BM25 无上界 vs 余弦 [-1,1] 量纲冲突）
                        ↓  取前 fuse_top_k
        RerankerProvider.rerank（交叉编码精排）
                        ↓
        返回 (原始下标, 分数[])，按分数降序

EpisodeMemory 额外一层：场景匹配（applicable_scenes 命中 scene_key）+ quality_score / success 参与排序

写入侧的分界：memory 不理解游戏

「这次按键发生了什么、影响了哪一格」由 harness 判定（object_interactions.py 按 kind 方法表产出 dialog / warp / still 事件），再作为数据交给 memory；memory 只按键原样读写 + 维护倒排索引与向量缓存，不做语义判定。

写入契约：同局 step 单调不减（恢复时先截断）；事件一旦落库不可变，修正只能靠新事件或 resume 截断。Store 出口 assert 这条 invariant。
