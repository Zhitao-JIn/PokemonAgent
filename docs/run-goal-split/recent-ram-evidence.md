# Run 判定最近五次 RAM 证据（637）

用户要求 run 判定器同时取得最近五次“读 RAM 的观测”，用于解决机械评分确认满血而模型文字视野没有 HP 数值的问题。这是对 W2 原有“RAM 只供机械测评”的明确例外，改变 agent 的 run 判定证据范围；不改变机械判据、模型型号、预算或状态图。

- 只有 run.review_and_judge 填充 `ram_observations`；episode/task 判定的调用方不填，规划和动作调用也不新增此字段。
- 从 TraceToolPort 读取当前 run_id 与 branch 的账本，选所有层已落盘的 sense_frame 中带 RAM 的最近五条。先筛 run/branch，再按 ended_at、seq 排序，最后取五条并保持时间先后。
- 不同来源的实际观测都保留，不因为数值相同而合并；无 RAM 的合法旧事件跳过，不补值；损坏事件显式校验失败。没有观测时提供“未提供”，不能据此宣称达成。
- 来源事件 ID、来源节点、步号、时间与序号跟随读数。RAM 包含完整结构化读数，例如队伍、金钱、背包和屏幕解码，不能与旧协议下仅屏幕文字的可见范围混为一谈。
- harness 使用 Pydantic 观测模型；tool 将 world 的读数模型序列化为 prompt 自己的文字契约；brain 只收到渲染文字，不新增对 world/harness 的依赖。RunState 不新增持久状态，RAM 历史只从账本读。
- judge_success 新增 v5，固定读法在动态输入之前；旧版本不改。RAM 只进入该次模型 prompt，原有截图来源不变，也不新增模型调用。
- result_grade 继续复用最后一次 run 判定的文字 prompt，因此能看到数值；不另接模拟器或机械 scorer 的结论，不修改独立评分规则。

五条是有限历史窗口，可能不含开局受伤帧。它能补足最新 HP 等直接状态，却不能保证每一个跨帧判据都能只靠这五条成立；仍须结合现有历史证据。新增输入会改变 token 成本与停机行为，下一次付费对照必须重测基线，旧分数/trace 不追改。
