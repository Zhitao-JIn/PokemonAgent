# 商店光标核对

用户反馈 shop_items 的光标位置一直不对。本次对98个已标为 shop_items 的冻结帧分别核对：
截图中实心箭头像素、冻结 wTileMap 的0xED箭头、ScreenText.cursor。

## 结果

7帧的截图与冻结RAM实心箭头证据不一致：

| 帧 | 截图实心箭头（行、列） | RAM实心箭头（行、列） |
|---|---|---|
| c-0491 | (4, 5) | 无 |
| c-0493 | (8, 5) | 无 |
| c-0497 | (4, 5) | 无 |
| c-0560 | (3, 1) | 无 |
| c-0565 | 未检出 | (6, 5) |
| c-0568 | (8, 5) | 无 |
| c-0589 | (8, 5) | 无 |

坐标从0起。截图与CPU侧图块缓冲是不同素材，读取时菜单更新可能尚未显示到截图，
不能直接把截图箭头位置当作该冻结RAM的答案。7帧中6帧截图仍有实心箭头而RAM已无，
1帧RAM已写实心箭头而截图尚未检出。

另外91帧只确认箭头位置一致，不保证商品、数量、对话或所有像素同步。
98帧的当前cursor字段与冻结RAM箭头所在选项没有发现矛盾；
不能仅凭上述截图错位就把正确的RAM光标读取改为截图里的旧位置。

## 方法与局限

`scripts/label_cursor_evidence.py` 只读原图像素及冻结RAM，不调用待测文字解码器生成箭头答案。
截图中实心横向箭头的5×7核心字形在 p-shop_menu 核对过，按像素精确匹配。
核心定位不要求图形在8×8格内同一垂直相位：takeover:shop_items 的箭头上移1像素，
完整8×8模板会漏检，核心匹配能找到，因此不把此帧误计为不同步。
方法针对本数据集商店截图；未检出表示该固定字形匹配没有找到，不能推广为任意字体的通用OCR。

0xEC空心▷是上层选择标记；0xEE向下▼是文本续页或滚动提示。
两者不是当前的实心▶光标。cursor_cell 是 option_grid 内的行列，
与20×18物理屏幕行列、滚动后的全商品索引也不同。

## 审阅页调整

- 98个商店帧新增独立光标证据栏：截图箭头坐标、RAM箭头坐标、候选cursor。
- 截图绿色框只框出像素检出的实心箭头，不把RAM坐标画在可能不同步的截图上。
- 新增“截图 / RAM 光标不一致”筛选与7帧的明确提示。
- 既有48帧用户审核记录保持，原始截图、RAM、真值和审核资格未修改。

证据在 `eval_results/labeling_1007/shop_cursor/cursor_evidence.json`，
新版HTML内也保存每个商店帧的箭头证据。不同步帧可审RAM字段，但不能作为“截图与RAM一致”的通过证据；
需要这种对应关系时，应从完整存档重新采集稳定素材，不能凭WRAM补画原截图。

本次修正的是审阅页对照方式，没有根据错位截图修改decoder或现有RAM真值。
