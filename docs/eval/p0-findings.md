## 二、覆盖判定规则（E2 照做）

**规则**：一帧里没有光标 `▶` → 已覆盖（对话框照常读，没有选单）。有光标时，以下任一成立 → **未覆盖**：

1. 光标左边找不到框的竖边 `│`（队伍列表、图鉴都是这种）；
2. 有光标却切不出任何选项；
3. 光标所在框的各行里，有文字没有被分进任何一个选项。忽略三种行：`×` 开头（数量）、`¥` 开头（价格）、只由 `-` 组成（空招式位）。

**验证**：26 个界面，期望与结果全部一致（0 误判）。

| 期望"已覆盖"（20） | 期望"未覆盖"（6） |
|---|---|
| 开始菜单、背包、背包子菜单、存档 YES/NO、队伍子菜单（野外 / 战斗）、能力页、图鉴条目、城镇地图、训练家卡片、战斗 2×2、招式列表、战斗背包、商店 BUY/SELL/QUIT、商品列表、对话框、野外无界面、战斗开场文字、标题菜单、取名列表 | 队伍列表（野外 / 战斗）、图鉴列表、图鉴右侧菜单、选项设置、起名键盘 |

第一版规则在招式列表上误判了一次（空招式位显示 `-`），加上第三条的"只由 `-` 组成"之后清零。

## 三、战斗状态框（W1）与对手名字（D4）

4 份战斗存档（`battle_action_menu`、`catch_weaken_target`、`battle_pokemon_switch`、`catch_throw_ball`）逐项核对，变量读数与屏幕**全部一致**：

| 字段 | 地址 | 来源 |
|---|---|---|
| 我方名字 | `wBattleMonNick` = 0xD009 | 新增，见下 |
| 我方等级 / HP / 最大 HP / 状态 | 0xD022 / 0xD015（2 字节）/ 0xD023（2 字节）/ 0xD018 | `capture_manual_play.py` 已编译验证 |
| 对手名字 | `wEnemyMonNick` = 0xCFDA | 新增，见下 |
| 对手等级 / HP / 最大 HP / 状态 | 0xCFF3 / 0xCFE6（2 字节）/ 0xCFF4（2 字节）/ 0xCFE9 | 同上，已编译验证 |

**两个名字地址（D4）**：pokered 源码 `ram/wram.asm` 里 `wEnemyMonNick:: ds NAME_LENGTH` 紧挨在 `wEnemyMon::` 之前，
`wBattleMonNick` 与 `wBattleMon` 同理；`NAME_LENGTH` = 11。由已编译验证的 `wEnemyMon`（0xCFE5）、`wBattleMon`（0xD014）各减 11，
得 0xCFDA、0xD009；4 份存档实读都与屏幕一致（RATTATA / PIDGEY / BULBASAUR），名字以 0x50 结尾。
**没有真的跑 rgbds 编译**（设备上没有工具链），是"源码布局推算 + 实读"两条互证。D4 按"读内存名字字段"落地，不用查表。

`foe_hp` 从视觉的五档文字变成精确数值（如 15/15），下游同步见 plan E1。

## 四、两处解码缺陷的修法（E2 照做）

**1. 对话框被小菜单压住时混进菜单字**：读对话框每一行时，**遇到第一个边框图块就截断**（原来整行读到右边框）。

| 界面 | 现在 | 修后 |
|---|---|---|
| 队伍子菜单（野外） | `Choose a P SWITCH CANCEL` | `Choose a P` |
| 队伍子菜单（战斗） | `Choose a P STATS CANCEL` | `Choose a P` |
| 普通对话、存档 YES/NO、商店两处、队伍列表、战斗开场文字 | 各自原文 | 不变 |

（`Choose a P` 是因为句子后半截被菜单盖住了，屏幕上就只露这么多，视觉看到的也一样。）

**2. 价格与数量被丢掉**：按选项顺序另出一个对齐的列表，把 `×` / `¥` 行挂到它上面那一项：

| 界面 | 修后（选项 → 附注） |
|---|---|
| 商品列表 | POKé BALL → `¥200`，ANTIDOTE → `¥100`，PARLYZ HEAL → `¥200`，BURN HEAL → `¥250` |
| 背包 | TOWN MAP → 空，POKé BALL → `× 4`，CANCEL → 空 |
| 战斗背包 | POTION → `× 1`，CANCEL → 空 |
| 开始菜单 | 全空（不受影响） |

选项文字本身**不变**（不把价格拼进选项，免得判据里的名字比对被打乱）。
