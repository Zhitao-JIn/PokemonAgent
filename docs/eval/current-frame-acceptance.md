# 当前帧状态型评测验收

judge 已区分三类证据：描述“现在是什么”的状态型条件只看最后一条“之后变成”里的当前帧；要求某件事“发生过”的事件型条件可以查历史；要求变化的条件才跨帧比较。judge_success.md 现再明确：状态型目标若只在历史帧满足、最终帧已不满足，必须判未达成。

商店交互目标现在要求结束时最终当前帧同时满足 overlay=choice 和 options=[BUY, SELL, QUIT]。旧机械 scorer 曾把这项状态当成事件，只要历史上出现过主菜单便通过，和 judge 的状态判据不一致。scorer 现在只核对最后一个解码帧；最终帧缺选单或解码帧缺失时不会从历史帧推定通过。

为了保留旧实验含义，新数据集版本 v20261021_current_state 从 v20261021_corrected 复制而来，默认评测配置已切到新版本。只改商店用例的验收文字，其他样本与 RAM 来源保持原值。商店和治疗两个归档都经生产打包器重打；治疗归档继续使用直接写 RAM 生成的受伤起点（首只 12/25、第二只 15/15），打包器从实际模拟器观测验证受伤条件。

本次已运行 70 个相关评测测试、全仓库 ruff check . 与 ruff format .。没有重新运行模型端到端评测；此前按旧数据版本采集的商店运行仍按旧目标解释，不能当作新状态型目标的回归结果。
