# 量表（rubric）草稿——二分版

> 关联：`docs/eval/metrics/intent.md`。状态：待确认。人工审核通过前不当作指标使用。

## 一、形式

- 每条量表是**一个是/否问题**。输出四种之一：`是`、`否`、`未知`（证据不足）、`不适用`。
- LLM 标注，每条必须返回：`verdict`、`evidence`（从输入里原样引用的片段，可多处）、`reason`（一句话）。没有证据引用的"是"一律改记`未知`。
- 人工只审核：所有`否`与`未知`逐条看；`是`先抽 20% 看，抽检里出现分歧就扩大抽检；记录 LLM 与人工的一致率，一致率不够的条目先改问题措辞。
- `未知`与`不适用`不进分母；每条单独报通过率，不合成总分；节点另报"全部适用条目都为是"的比例。
- 评分模型与被测模型不同。

## 二、写法规则

1. 一个问题只问一件事；问法里必须含可观察的判定标准（"是否每个…都…"），不用"是否合理""是否清楚"。
2. 每条给出：什么情况判`是`、什么情况判`否`、一个反例。
3. 能机械判的进契约，不进量表。
4. 红线不进量表。
5. 原来的三档拆成多个独立的是/否问题，不保留"部分满足"。

## 三、节点量表

| item_id | 节点 | 问题 | 判"是" | 判"否" | 反例（应判"否"） |
|---|---|---|---|---|---|
| plan_covers_goal | 规划 | 总目标要求的每一项，目标表里是否都有对应条目 | 逐项对照，每项都找到对应条目 | 有一项找不到对应条目 | 总目标含"取包裹、送到"，表里只有"取包裹" |
| plan_no_irrelevant | 规划 | 目标表里是否没有与总目标无关的条目 | 每个条目都能对应到总目标的某一项 | 有条目对应不到任何一项 | 总目标是送包裹，表里多了"抓一只宝可梦" |
| plan_order_valid | 规划 | 被依赖的条目是否都排在依赖它的条目之前 | 每对依赖都满足先后 | 有一对依赖颠倒 | "交付"排在"取件"之前 |
| decompose_executable | 拆分 | 每个 task 是否都能由当前动作空间里的动作完成 | 每个 task 都有至少一条可行的动作序列 | 有 task 需要动作空间里没有的操作 | task 要求"查看队伍等级总和" |
| decompose_granularity | 拆分 | 每个 task 是否只含一个可单独验收的子目标 | 每个 task 对应一个可验收结果 | 有 task 塞了多个可验收结果，或细到单次按键 | 一个 task 同时要"进商店并买球并出来" |
| decompose_criteria_visible | 拆分 | 每个 task 的判据是否只依赖当前能观察到的证据 | 判据里的证据都能在画面或 RAM 读数里看到 | 有判据依赖观察不到的信息 | 判据写"店员心情好" |
| decompose_info_available | 拆分 | 每个 task 所需的信息是否都在当前观察或记忆里 | 所需信息都能找到出处 | 有信息找不到出处 | task 写"走到 (29,19)"，但坐标没出现过 |
| judge_cites_evidence | 判定 | 结论是否引用了输入里能找到的具体证据 | 结论所依据的证据在输入里有原文 | 结论没有依据，或引用的内容输入里没有 | 判"达成"，理由是"看起来完成了" |
| judge_evidence_consistent | 判定 | 引用的证据是否与结论一致 | 证据支持结论 | 证据与结论矛盾 | 引用"HP 12/25"，却判"队伍满血" |
| summary_no_fabrication | 摘要 | 摘要里的每条陈述是否都能在输入里找到 | 每条陈述都有出处 | 有陈述在输入里找不到，或把推断写成事实 | 输入没说原因，摘要写"因为对手太强" |
| summary_keeps_key_info | 摘要 | 后续任务要用的关键信息是否都保留 | 先列出输入里后续要用的信息，每项在摘要中都有 | 有一项缺失 | 丢了收件人名字 |
| summary_attributed | 摘要 | 关键信息的对象与时间是否都写对 | 每条关键信息的归属对象与先后都与输入一致 | 有一条归属或先后写错 | 把顾客甲的话写成顾客乙说的 |
| summary_states_cause | 摘要 | 是否说明了成败原因，且原因在输入里有依据 | 有原因且有依据 | 没有原因，或原因没有依据 | 只写"失败了" |
| summary_reusable | 摘要 | 是否含有能指导下一次行动的具体信息 | 至少有一条可直接用于下次决策的具体事实或做法 | 只有流水账，没有可用信息 | 全文只是按时间复述按键 |
| summary_consistent_concise | 摘要 | 是否无自相矛盾且无重复冗余 | 没有矛盾，也没有重复表述 | 有矛盾，或同一信息重复出现 | 前文写"成功"，后文写"未完成" |
| summary_major_distortion | 摘要 | 是否出现重大失真（使后续决策出错的事实错误） | 无（需同时引用来源与候选两处证据） | 有（命中则本条摘要的保真类条目作废并单独计数） | 把"没进店"写成"已进店" |
| index_headline_accurate | 索引 | `headline` 是否准确概括该单元做了什么，且没有摘要与 `facts` 里不存在的内容 | 逐项对照，`headline` 的每个说法都能在摘要或 `facts` 里找到 | 有说法找不到出处，或与 `facts` 矛盾 | `headline` 说"拿到了收件人"，而 `facts` 里没有对话 | 新增 |
| index_keys_cover_key_info | 索引 | 后续任务要用的关键信息是否都在 `keys` 里（或 `headline` 里） | 先列出该单元里后续要用的信息，每项都在 `keys` 或 `headline` 里 | 有一项缺失 | `facts` 里有收件人 PROF. OAK，`keys` 里没有 | 新增 |

> 摘要与索引共八个问题（摘要六个、索引两个）；摘要的六个问题对应原来的五个维度：保真、关键信息、因果、复用、一致与简洁，其中"关键信息"拆成了"保留"与"归属"两条。

## 四、数据集质量量表（评分对象是样本，不是节点）

| item_id | 问题 | 判"是" | 判"否" | 不适用 | 反例 |
|---|---|---|---|---|---|
| criteria_observable | 完成信号是否能对应一条机械判据 | 能指出对应的判据与它读取的字段 | 写不出对应判据，或要靠推断 | — | "把事办好"，没有可读字段 |
| criteria_scope_checkable | 范围是否用可核对的说法 | 对象与数量都可核对，如"至少两位不同对象" | 用了"全部"等含不可达对象的说法，或对象不清 | 目标无范围要求 | "与店里所有人对话"（柜台里的人走不到） |
| criteria_stop_stated | 终点是"停在某状态"时，是否写明停手 | 写明不要做什么 | 没写，且存在越界风险 | 终点不是停在某状态 | "把光标移到 RUN"，没写不要按 a |
| criteria_distinct | 接近完成的状态是否会被判为未完成 | 差一格、差一步的状态按判据为未完成 | 接近状态也能判完成 | — | 判据"站到门附近"，站在门前一格也算 |

## 四点五、按步观察之后的变化（2026-10-28）

- 摘要的 `facts` 由程序机械摘取，不进量表；`summary_*` 各条评的是 LLM 写的解读与索引，评分输入里带上 `facts`。
- 索引的机械检查（`keys` 字面出现、`evidence` 取自固定词表、`headline` 结局词与来源章一致）在解析器里，不进量表；新增两条语义量表 `index_headline_accurate`、`index_keys_cover_key_info`。
- 评测用的 trace 与记忆须是迁移后的新格式（不兼容旧数据）。

## 五、与上一版的差异

- 三档改为二分；原来每条的三档拆成独立的是/否问题。
- `choose_fit` 取消；动作选择不设量表。
- 数据集质量四条改为二分，`criteria_scope` 改名为 `criteria_scope_checkable`，`criteria_stop` 改名为 `criteria_stop_stated`。
- 沿用的现有量表：`decompose_quality` 拆成 `decompose_executable`、`decompose_granularity`、`decompose_criteria_visible` 三条；摘要五维拆成六条。现有 `rubric.json` 里的三档定义不改，新量表是另起一套，不覆盖旧版。
