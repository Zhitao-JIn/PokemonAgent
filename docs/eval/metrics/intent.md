# intent —— 评测指标与量表

> 流程位置：**intent.md**（待确认）→ spec → plan
> 关联：`docs/eval/mid_tasks/intent.md`（三档任务）、`docs/eval/task_boundary/intent.md`（边界六要素）、`evals/agent_short_goal_run/dataset/*/rubric.json`（现有量表格式）、`evals/brain_summary/contract.py`（摘要五维）
> 状态：待确认。

## 一、一句话意图

把评测指标分成三份：端到端实验指标、逐节点指标、数据集质量门禁；每个节点的指标按"判据来源"分层（契约 / 真值 / 量表），"可信度"按节点职责定义，不统一套成判定器准确率。

## 二、三条原则

1. **数据集质量是门禁，不是指标。** 不可判（机械判据返回 N）、起点不合格、判据拒绝合理读法，都是数据集错误：先修数据集，通过门禁才允许跑实验；它们作为错误原因记录，不进入任何节点或端到端的得分。
2. **判据来源分三层，不混成一个分数。**
   - 契约：只凭请求与答案就能由代码判，不需要标签（表操作合法、动作在动作空间内、参数类型与范围）。
   - 真值：有独立得来的标签，机械比对（可接受集合、判定真值、召回真值）。
   - 量表：语义判断，**二分**（是 / 否，另有"未知""不适用"），每条要引用输入里的证据；由 LLM 标注，人工只审核；评分模型与被测模型不同。
3. **只评输出质量，不称置信度。** 节点目前只输出决策与理由，不输出"有多确定"，所以不报校准指标；质量得分不称为置信度。

## 三、端到端实验指标

| 维度 | 指标 | 要回答的问题 |
|---|---|---|
| 任务质量 | 成功率、约束违反率、红线命中率 | 是否完成原目标，是否满足顺序、预算、否定式约束 |
| 稳定性 | 重复运行成功率、pass@k | 单次是否可靠，多次尝试能否完成；分别报告 |
| 执行效率 | 动作数、调用数、重复动作率、完成后过冲 | 是否存在无效执行、达到目标后仍继续操作 |
| 资源成本 | 每任务 Token、耗时、已记录费用 | 完成任务要付出多少资源；成功与失败分别统计 |
| 记忆收益 | 不同记忆条件下的成功率、约束满足率与成本差异 | 对应层级的记忆是否帮助完成任务（需先有消融开关） |

按业务场景、任务层级、记忆条件和设计因子分组；设计因子不提前当成已标定的难度。

## 四、逐节点指标

只有**任务判定**和**记忆检索**有真值指标；其余节点只用契约（机械）与二分量表。

| 节点 | 契约（机械） | 真值（有标签） | 量表（二分，LLM 标注、人工审核） |
|---|---|---|---|
| 规划与拆分 | 表操作合法、新增条数不超限、预算为正、目标与判据非空（沿用 `contract_checks`） | 无 | 7 条：`plan_covers_goal`、`plan_no_irrelevant`、`plan_order_valid`、`decompose_executable`、`decompose_granularity`、`decompose_criteria_visible`、`decompose_info_available` |
| 动作选择 | 动作合法率、参数正确性、解析失败率 | 无 | 无 |
| 任务判定 | 输出结构有效率 | FP、FN、FPR、召回率（按难负例类别分组，N 不进分母） | 2 条：`judge_cites_evidence`、`judge_evidence_consistent` |
| 摘要与记忆写入 | 输出结构有效率；索引三条机械检查（`keys` 字面出现在依据文本里、`evidence` 取自固定词表、`headline` 的结局词与来源章一致，检查在摘要解析器里，不过即重试）；`facts` 等于对本 task 观察序列做 `changes()` 的结果（回归测试，不是评分）；上层 `facts` 不存在 | 无 | 8 条加重大失真（原 6 条加 `index_headline_accurate`、`index_keys_cover_key_info`） |
| 记忆检索 | 无 | Recall@k、MRR、干扰占比（补齐检索真值后才报，此前不报） | 无 |

- 动作选择不再报"可接受率""越权率"（它们依赖人审的可接受集合）；现有 `brain_choose` 冻结数据集保留，只作诊断，不作指标。
- 约束违反率只在端到端层报，不在节点层报。

## 五、数据集质量门禁

门禁通过才能跑实验；任何一项不过，先修数据集。

| 类别 | 检查 | 方式 |
|---|---|---|
| 起点 | 起点通过预检（`dataset/build/preconditions.py`） | 机械 |
| 判据 | 机械判据对每条样本都能给出明确结论，不可判数为 0 | 机械 |
| 判据 | 判据接受无边界目标文的所有合理读法 | 冻结时人工列合理读法逐条过判据 |
| 复现 | 确定性 oracle 通过判据，冻结哈希一致 | 机械 |
| 标签来源 | 每个标签的来源已记录（机械判据 / 规则算出 / 人工），自动收集与自动标注分开说明 | 记录 |
| 验收描述 | 对应任务边界六要素 | 二分量表：`criteria_observable`、`criteria_scope_checkable`、`criteria_stop_stated`、`criteria_distinct`（见 `docs/eval/metrics/rubrics.md`） |

数据集规模、各业务场景与任务层级的覆盖量单独报告，用来说明覆盖，不当成得分。

## 五点五、按步观察之后的口径变化（2026-10-28）

依据 `docs/step_observation/spec.md`（v1.17）：摘要由三块组成——来源章（机械）、`facts`（机械，只在 task 层，不经 LLM）、解读与 `index`（LLM 同一次调用产出）。因此：
- "事实是否漏了、写错了"不再由量表评，由 `facts` 的回归测试保证；`summary_*` 量表只评 LLM 写的那部分（解读与索引），输入里包含 `facts`。
- 索引的"关键词有没有出处、成败词对不对、evidence 是否在词表里"是机械检查，不进量表；量表只评语义：`headline` 是否准确、`keys` 是否覆盖了后续要用的关键信息。
- 数据集质量门禁新增一条：用于评测的 trace 与记忆须是迁移后新格式（不兼容旧数据，旧数据整体重建；见 ROADMAP P-2）。
- 2026-10-28 审计后补的**摘要契约检查**（机械，不评分，对应 spec D27–D30，测试里断言）：
  - `facts` 的步号坐标：`step` 是局内步号、`sub` 是脚本内序号，两者分别断言；`pointers` 的步号区间两端包含，且能定位回子记录。
  - `grounding_texts` 的每一项都是该次摘要调用实际渲染出的提示词的子串（依据只来自模型看得见的文字）。
  - 机械收尾（预算终止、整局异常，不调用模型）在有证据时也产出非空 `facts`、`pointers`，与走 LLM 的路径产出一致。
  - 摘要端口的 `grounding_texts`、`termination` 必填；有正文的结果必须有非空 `headline`；旧记忆缺新字段时读取报错。

## 六、不做

- 不把"不可判比例"放进任何指标。
- 不为动作选择设语义量表，也不设真值指标（只留契约）。
- 不在检索真值补齐之前报检索排序指标。
- 不报置信度校准指标；节点先输出置信度、并且有独立标签，才另开一组。
- 不把量表得分与真值指标合成一个总分。
