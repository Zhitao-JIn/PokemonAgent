## 一、一句话意图

补 5 条中期样本：每条在一个 run 内完成，由 2–3 个自然的 episode 接力；长度来自必要依赖，成败只靠 RAM 与账本机械判定；每条写明关键证据在哪个 episode 出现、隔多久仍要用。

## 二、三档任务的定义

> **口径更正（2026-10-28）**：本节按"完成范围"定义三档，是旧说法。三档的性质、"冻结是评测手段、与分层正交"、"规划器给的条件只用于评测"以 `docs/eval/tiers.md` 为准。

| 档 | 完成范围 | 能看到的过去 | 本文 |
|---|---|---|---|
| 短期 | 一个 episode，可含多个 task | 同 episode 过往 task 的背景索引 + 当前 task 的 action 记忆 | 现有 20 条（都只有一个 episode）|
| 中期 | 一个 run，含多个 episode | 过往 episode 的索引 + 当前 episode 的详细 task 记忆 | **本文 5 条** |
| 长期 | 多个 run | 过往 run 的背景索引 + 当前 run 内全部 episode 记忆 | 不做 |

- "过去"都是运行时自己产生的，起点存档不需要带记忆，从空记忆起跑即可。
- 长期任务需要跨 run 的非空记忆起点（retest5 覆盖表的缺口），本次不做；中期也因此不测"过往 run 索引"。

## 三、共同约束

1. **一个 run、多个 episode。** 每条的最短路线里都有至少两个自然边界：换地图并且换了一个独立子目标。planner 实际拆成几个 episode 由它决定，判据不依赖拆法（沿用 run 粒度取整条执行线），样本报告 episode 数与 task 数。
2. **长度来自必要依赖。** 每条列"必要下限"（换图次数、最短移动步数、必须完成的对话与菜单）。冻结时用确定性 oracle 实测 `oracle_steps` 写进样本；运行时报 `agent_steps / oracle_steps` 监控凑长，不进成败。反复移动与重试不算依赖。
3. **完成条件只读 RAM 与账本**（金钱、背包、队伍、`map_id`、`place`、屏幕解码文字、`act_call`），不读模型文字。
4. **证据—使用表。** 每条写：证据是什么、出现在哪个 episode、最晚在哪被用、间隔（步数、换图数、episode 数）。
5. **起点来自现有 `.state`**：M1、M4 原样；M2、M3、M5 各做一次只改一个字节的派生（沿用 `dataset/build/injured_start.py`）。每个新 `check_id` 在 `dataset/build/preconditions.py` 加起点预检。
6. **尽量避开草丛**：除 M1 必经的 Route 1 与 M3 回城的一小段外，全在城镇与室内。

## 五、五个任务

### M1 `mid_walk_to_pallet`（2026-10-28 改：去掉包裹，改为长距离移动加知识使用）

> 改动原因：原设计的包裹送达在模拟器里没有成立。M1 原起点 `knowledge_pokemon_center_enter` 的事件位 `0xD74E` 是 `0x03`，包裹这一幕早已过去，进店不会触发托付，背包也不会出现 item 70；清掉 bit1 仍不触发。包裹交付改留给长期任务 L1（起点用 `knowledge_dialogue_advance`，那里 `D74E=0x00`、托付对话正在进行）。

- **起点**：`knowledge_pokemon_center_enter.state` 原样，不派生。地图 1 (20,26)；Bulbasaur L7 25/25、Pidgey L3 15/15；背包 POTION×1、POKé BALL×4；钱 2000。
- **目标**：「走到真新镇，再走进大木研究所。」
- **给 judge 的判据**：「人已进入大木研究所（地图 40）。」
- **自然 episode**：① 出城（地图 1→12）② 赶路（12→0）③ 进研究所（0→40）。
- **路径（已实测）**：常青市南口 `(21,35)` → 1 号道路 map 12 `(11,0)`；1 号道路南端 `(11,35)` → 真新镇 map 0 `(11,0)`；研究所门 `(12,11)` → map 40 `(5,11)`。真新镇三栋建筑门口：玩家家 `(5,5)`→map 37，对手家 `(13,5)`→map 39，研究所 `(12,11)`→map 40；两栋住宅在北侧一排，研究所在较南、中央偏东。1 号道路 `(11,12)` 南侧有墙，要经东侧草丛绕到 `x≈15` 再回 `x=11`。
- **必要依赖**：目标文不写坐标与路线；路线事实只在知识库里（见下）。1 号道路有草丛，会遇到野生宝可梦，必须处理（逃跑或战斗）才能继续；同一路线的遇敌次数随时机变化。
- **oracle 实测（现行等待）**：无遇敌 6 个决策步、69 次按键、3 次换图；25 次采样全部到达研究所，决策步最小/中位/最大 6/22/98，按键 69/92/218，15 次遇敌 ≥1 次（遇敌率 60%，共 50 次遭遇）。每次遇敌用"按 a 进战斗菜单→`battle_run`→等回行走场景"约 16 个决策步，全部一次逃脱；队伍 HP 无变化。遭遇地点集中在 map 12 的 `x=7–15, y=9–33`。同一空转帧下重复结果完全一致，说明确定性由 RNG 状态决定，**不是独立随机样本**；真实 agent 的节奏不同，遇敌次数会不同。
- **机械判据 `walk_to_pallet`**：起点 `map_id == 1` 否则 N；存在帧 i1 `map_id == 12`；存在帧 i2 > i1 `map_id == 0`；存在帧 i3 > i2 `map_id == 40`；终局不在战斗、无选项。单列度量：遇敌次数、战斗内决策数（不进门槛）。
- **证据与使用点**

| 证据 | 出现的位置 | 最晚使用点 | 间隔 |
|---|---|---|---|
| E1 路线事实（南口通 1 号道路、南端通真新镇、研究所是较南的大房子） | 知识库，按地图与目标文召回 | ①②③ 每个 episode 的去向选择 | 贯穿全程 |
| E2 "已在 1 号道路 / 已到真新镇" | ①②的终局画面与账本 | ② 的去向与 ③ 的"到哪找研究所" | 跨 1 个 episode 边界 |

  这条的主要测试点是"知识被召回并用上"与长距离移动，不是跨 episode 的事实记忆（那由 M2、M4 承担）。
- **知识原子（新增一条）**：连接关系，见 `docs/eval/mid_dataset/spec.md` D9；只写方向与地标，不写坐标与按键；消融：开 / 关这一条。
- **风险**：遇敌使步数方差很大（6 到 98 个 oracle 决策步），`k_metric` 取 `pass_at_k`，战斗步数单列，不与移动步数混报。

### M2 `mid_heal_buy_return`

- **起点**：派生自 `knowledge_pokemon_center_enter.state`，首只 HP 改为最大 HP 的一半。地图 1 (20,26)，钱 2000，球 4。
- **目标**：「先去宝可梦中心把队伍治好，再去商店买 2 个精灵球，最后回到你现在站的这个位置。」
- **给 judge 的判据**：「队伍满血；精灵球比开始多 2 个、钱少 400；人回到了开始时站的格子。」
- **自然 episode**：① 治疗（1→41）② 购买（41→1→42）③ 回原位（42→1）。
- **路径**：中心门 (23,25) → 柜台前 (3,3) 朝北与护士说话 → 商店门 (29,19) → 柜台前 (2,5) 朝西 → BUY → 球 ×2 → 回 (20,26)。
- **必要依赖**：顺序写死；起点坐标只在开局第一帧可见，目标不给坐标；数量与花费必须精确。
  必要下限（估算）：换图 4 次，移动 ≥ 60 步，对话与菜单按键 ≥ 20。
- **机械判据 `heal_buy_return`**：起点有伤员否则 N；存在帧 i_heal（`map_id == 41` 且全员满血）；终局球 = 起点 + 2、钱 = 起点 − 400、除 item 70 外背包不变；i_buy > i_heal；终局 `(map_id, x, y)` 等于起点且不在战斗。包裹事件未触发时进店会自动给包裹，判据不计 item 70。
- **证据与使用点**

| 证据 | 出现的 episode | 最晚使用点 | 间隔 |
|---|---|---|---|
| E1 起点坐标 (1, 20, 26) | ① 开局第一帧 | ③ 最后一步 | ≥ 60 步、4 次换图、跨 2 个 episode |
| E2 治疗完成（满血 @ 41） | ① | 证明先治后买 | 到购买成交 ≥ 20 步 |
| E3 购买成交 | ② | ③ 与终局 judge | 到终局 ≥ 20 步 |

  附带度量：起点坐标有没有被写进后续 episode 的目标文，区分"靠目标文传递"与"靠记忆传递"。
- **知识原子**：宝可梦中心、商店购买流程、门与换图（现有）。

### M3 `mid_catch_then_heal`

- **起点**：派生自 `knowledge_catch_weaken_target.state`，Bulbasaur 的 HP 改为最大的一半。已在野生战斗中，地图 12 (13,7)，对手 Lv3、最大 HP 15（读自存档 RAM，待核）；POKé BALL ×4。
- **目标**：「把眼前这只野生宝可梦抓住，然后把整支队伍（包括它）治到满血。」
- **给 judge 的判据**：「队伍多了一只；战斗已结束；整支队伍满血，且是在抓到之后治的。」
- **自然 episode**：① 战斗内抓捕（削弱 → 投球 → 拒绝起名 → 战斗收尾）② 回城治疗（12→1→41）。
- **必要依赖**：对手只有 15 HP，一击大概率打掉一半，第二击可能击倒（以 oracle 为准），所以"再打还是投球"取决于前一击实际掉了多少（episode ① 内、task 间的依赖）；抓到后的起名询问必须拒绝；治疗必须在抓到之后，新成员本身是被削弱过的，必须包含在内。
  必要下限（估算）：episode ① 约 15–25 个 agent 动作，② 移动约 20–30 步（Route 1 北段到城镇，再到中心门 (23,25)）。
- **机械判据 `catch_then_heal`**：终局队伍数 = 起点 + 1；存在帧命中捕获成功（沿用 `catch._ball_result` 的成功分支）；存在帧 i_heal 在捕获帧之后，`map_id == 41` 且全员满血；终局不在战斗、无选项、无起名键盘；对手 HP 从未为 0。非门槛度量：投球时对手 HP 是否低于最大、用球数、攻击次数。
- **证据与使用点**

| 证据 | 出现的 episode | 最晚使用点 | 间隔 |
|---|---|---|---|
| E1 对手 HP 轨迹（15/15 → 一击后 X/15） | ① 战斗内 | ① 里"再打还是投球"的决定 | ≤ 约 10 步，同一 episode 的 task 记忆 |
| E2 新成员已加入、且是被削弱后抓到的 | ① | ② 治疗时判断"整队"与是否需要治 | ≥ 25 步、2 次换图、跨 1 个 episode 边界 |

- **知识原子**：捕捉、战斗行动、宝可梦中心、菜单与选项（现有）；"起名询问怎么拒绝"缺。
- **风险**：回城途中 Route 1 北段有草丛，可能遇怪；`k_metric` 取 `pass_at_k`。

### M4 `mid_customers_hint_buy`

- **起点**：`knowledge_shop_interaction.state` 原样。地图 42 (3,5)；钱 3000；Bulbasaur 5/25；POTION×1；店员 (0,5) 在柜台后，顾客一位在 (3,3)，另一位沿 x=5 来回走。
- **目标**：「先问问商店里的两位顾客，再去宝可梦中心把队伍治好，最后回商店买 1 件其中一位顾客提到过、店里又确实在卖的东西。」
- **给 judge 的判据**：「两位顾客各说过话；队伍满血；买的是被提到且在售的那件；钱与背包只有这一笔变化。」
- **自然 episode**：① 问顾客（地图 42 内）② 治疗（42→1→41）③ 回商店购买（41→1→42）。
- **现场事实**（台词取自冻结数据集，价目取自 `shop_layouts.json`）：一位顾客说 `This shop sells many ANTIDOTEs.`，另一位说 `No! POTIONs are all sold out.`；BUY 列表：POKé BALL ¥200、ANTIDOTE ¥100、PARLYZ HEAL ¥200、BURN HEAL ¥250。被提到的两件里只有 ANTIDOTE 在售。
- **必要依赖**：台词只出现一次，之后画面和 RAM 里都没有；中间要离店治疗再回来；打开 BUY 列表时只有四件商品，靠记住"谁提了什么"才能选；走动的顾客位置会变，"两位不同的人"靠台词与位置区分，不能数按了几次 a。
  必要下限（估算）：换图 4 次，移动约 35 步，对话与菜单按键 ≥ 25。
- **机械判据 `customer_hint_purchase`**：解码文字中出现两句台词（容忍换行与大小写），记 iA、iB；存在帧 i_heal（`map_id == 41` 且全员满血）；终局相对起点 ANTIDOTE +1、钱 −100、其余三种商品数不变（不计 item 70）；顺序 max(iA, iB) < i_heal < 购买成交帧。
- **证据与使用点**

| 证据 | 出现的 episode | 最晚使用点 | 间隔 |
|---|---|---|---|
| E1、E2 两句顾客台词 | ① | ③ 选商品时 | ≥ 35 步、4 次换图、跨 2 个 episode，RAM 里不复存在，只有账本有 |
| E3 BUY 列表在售清单 | ③ | 与 E1、E2 取交集 | 须同时在上下文里 |

- **知识库混杂**：`shop_purchase` 原子里直接写了这两句台词和"顾客的话不等于店员"。知识库开着时，agent 不靠记忆也能猜出该买 ANTIDOTE；判据强制两句都出现过，防止绕过，但要看记忆的作用，必须读知识库关闭那一批的结果。

### M5 `mid_cure_poison_budget`

- **起点**：派生自 `knowledge_pokemon_center_enter.state`，把 Pidgey（第二只）状态字节改为中毒，其余不变（钱 2000，球 4，POTION×1）。
- **目标**：「队伍里有宝可梦中毒了。不要去宝可梦中心，用别的办法把它治好，总共花的钱不超过 150。」
- **给 judge 的判据**：「中毒的宝可梦恢复正常；全程没进过宝可梦中心；花费不超过 150。」
- **自然 episode**：① 去商店买药（1→42）② 出店后从背包使用。
- **必要依赖**：背包里的 POTION 治 HP 不治中毒，是干扰项；店里只有 ANTIDOTE ¥100 对症且在预算内，PARLYZ HEAL ¥200、BURN HEAL ¥250 不对症也超预算；买完要从背包使用（Start → ITEM → ANTIDOTE → USE → 选中毒那只）；"不要去中心"是否定式约束，要从 run 目标保持到每个 episode 的目标与 judge，而中心门离起点只有几步，最近的捷径就是违约。
  必要下限（估算）：换图 1–2 次，移动 ≥ 20 步，购买与使用菜单按键 ≥ 12。
- **机械判据 `cure_poison_budget`**：起点第二只状态 PSN 否则 N；终局该只状态 ok；全程无帧 `map_id == 41`；起点钱 − 终局钱 ∈ [100, 150]；钱减少的帧早于状态变 ok 的帧。
- **证据与使用点**

| 证据 | 出现的 episode | 最晚使用点 | 间隔 |
|---|---|---|---|
| E1 "不要去中心"的约束 | run 目标文 | ①②每一步的路线选择与每个 episode 的 judge | 贯穿全程 |
| E2 购买成交（钱 −100，ANTIDOTE +1） | ① | ② 使用药物，随后终局 judge 核"花费 ≤ 150" | ≈ 10 步，跨 1 个 episode 边界 |

  队伍菜单本身显示状态，"哪只中毒"不构成必须记忆的证据，不当记忆指标。
- **知识原子**：商店购买流程、门与换图（现有）；"状态异常对应的药""背包里使用物品""商店在售表"缺，这三处是本样本要暴露的缺口，不预先补。
