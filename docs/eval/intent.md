## 一、一句话意图

**任何时候，一条命令就能回答"这个 agent 现在有多好、比上一个版本好还是差、差在哪、花了多少"——
而且这个答案不依赖任何一个模型的自我评价。**

## 二、为什么现在做

1. **现在的成功率是模型说了算。** `Termination.GOAL_DONE` 是 `success` 的唯一来源，由 judge 模型给出；
   `docs/experiments/0827-knowledge-baseline.md` 机械复核 124 次 run：judge 记 115 次成功，实际 102 次（假阳 16、假阴 3）。
   当时的复核脚本已不在仓库。
2. **没有批次入口，也没有报表。** ROADMAP F1 📋；原 `evaluation/` 已整体删除（`docs/spec/README.md` 第四节）。
   `experiment/real_check/` 核的是"链路对不对"，明确"不能证格读到的 state 值"，更不回答效果。
3. **每一次改动都在盲飞。** 仅 0924 一天就有 28 条变更记录（CHANGELOG 201～228），其中多条改了 prompt、重试与判定，
   它们让 agent 变好还是变坏，目前只能靠看单局 trace 感觉。
4. **下游要用。** WikiSkill 的门控本身就是"验证集分数严格更高才接受"；B2、B8、C1、E1 的验收也都写成了对照实验。

## 三、测评维度

| 层 | 回答什么 | 典型度量 |
|---|---|---|
| **结果层** | 做成了没有 | 成功率（机械判定）、里程碑达成、pass^k（k 次全成）、judge 与机械判定的一致率（假阳 / 假阴） |
| **路径层** | 做的过程好不好 | 冗余按键、原地打转 / 重复访问、无效按键（画面与状态都没变）、停摆次数、终止类别分布（`Termination` 五类）、拆解质量、被打断后的恢复 |
| **效率层** | 花了多少 | token（按调用链路拆：`sense` / `choose` / `plan` / `decompose` / `judge` / `verify` / 两种摘要）、模型调用次数、墙钟时间、按键数、重试次数 |
| ~~安全层~~ | 有没有做不该做的事 | **本期不做**，下一期加；维度位置先留着，报表结构不因它改动 |

每一层都按**三种粒度**出数：task、episode、run（见 §五）。

## 四、测评方法：metric 与 rubric

**metric**：能从 trace 与世界状态直接算出的数。结果层与效率层全部用 metric；路径层能算的也用 metric（如无效按键数）。

**rubric**：一张按条目打分的评分表，用于"好不好"这类 metric 覆盖不了的路径质量（如"拆出的 task 是否可执行""卡住后换策略是否合理"）。规则：

1. **每个 rubric 条目先尝试写成机械判据**；写得出就不再让模型打分；
2. 必须由模型打分的条目，在报表里**单独标为"模型评分"**，与机械数字分栏；
3. 模型评分条目要**抽样人工标注做校准**，报出评分模型与人工的一致率——一致率不达标的条目不进结论；
4. rubric 条目、分值定义、评分 prompt 都版本化，跟任务集一样冻结；
5. 模型评分器与 agent 内部的 judge **不得是同一套 prompt**，否则等于让被测对象给自己打分。

## 五、数据集

**样本 = 一个 checkpoint + 目标 + 机械判据 + 类别标签（+ 可选的 rubric）**。checkpoint 由 `docs/checkpoint/intent.md` 提供，
保证每次都从完全相同的"世界 + 状态 + 记忆"起跑。

| 粒度 | 起点 | 终点 | 用途 |
|---|---|---|---|
| **task** | 某个 task 边界的 checkpoint | 这一个 task 结束 | 细粒度能力（走到某格、打开菜单、完成一次对战动作）；成本低、可大量重复 |
| **episode** | 某局开始前的 checkpoint | 这一局结束 | 拆解与 task 串联能力；带着前几局积累的记忆 |
| **run** | run 开始的 checkpoint | run 结束 | 长程推进：多目标、里程碑 |

**多样性要求**：类别覆盖（移动、对话、菜单、商店、战斗、捕捉、地图切换…）、记忆状态覆盖（空记忆 / 带积累记忆）、
难度覆盖（一次可成 / 需要多次尝试）。每个版本的数据集附一张覆盖表。

**来源**：① 人工设计：现有 `experiment/tasks.py` 20 条 + 钉死存档，迁为 task 级样本；
② 真机回收：从真实 run 的 task / episode 边界切出 checkpoint，按失败片段优先入库（为 ROADMAP F5 回归集做准备）。

**切分**：数据集可切 train / val / test，切分一经发布就冻结。

## 六、尺子自身的规矩

1. **机械判定是真值，judge 是被测对象。** 成败从世界状态直接核对（`map_id` / 坐标 / `scene` / `overlay` / RAM 读出的对话文字等 `Facts` 字段）。
   机械判不了的样本显式标"不可机械判定"，**不拿另一个模型去猜结果**。
2. **判定只在评测侧可见。** 机械判定器与 rubric 不进决策侧（ROADMAP A4、D1），否则 agent 会学到尺子本身。
3. **同口径才可比。** 每份报告钉住：git commit、工作区是否干净、各位置模型档、`config.py` 旋钮、数据集版本、rubric 版本。口径不同的报告不直接对比。
4. **盘上 trace 是唯一真相。** 所有数字从 trace 算出；报表是派生物，删了能重算。
5. **只读被测系统。** 测评不改 harness / brain / world 的行为；缺字段就提需求改 trace。
6. **集合冻结。** 数据集与 rubric 发布版本号后内容不改；要改就发新版本。
7. **不确定性要报出来。** 同一样本重复 k 次；每个数字带区间，对比带配对检验。
8. **成本与效果同表。**

## 七、范围

**做**
- 数据集的版本化定义（三种粒度）、覆盖表、切分；
- 批跑入口：给定数据集版本、重复次数、配置，从 checkpoint 起跑并落盘；
- 机械判定器；rubric 框架（含模型评分的校准流程）；
- 三个维度的汇总报表，机器可读（jsonl）+ 人可读（md 或 html）；
- 第一份正式基线：当前 main 在第一版数据集上的报告。

**不做**
- 安全层（下一期）；
- CI 回归门禁（ROADMAP F5）；
- 前沿模型参考线（A3）；
- 可视化看板 / 服务；
- 测评期间不调参刷分。

## 九、成功的样子（intent 层验收）

1. 一条命令跑完一个数据集版本，产出一份钉住口径的报告，覆盖结果 / 路径 / 效率三层、task / episode / run 三种粒度；
2. 报告给出当前产品的第一份正式基线，以及 judge 的假阳 / 假阴率；
3. 两份报告可以对比，并给出配对检验结果；
4. 模型评分的 rubric 条目附带与人工标注的一致率；
5. 报告里每个数字都能从盘上 trace 重算出来；
6. WikiSkill 复现可以直接把"在 val 集上跑一遍并取分"当作门控调用。
