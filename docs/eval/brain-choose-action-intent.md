# intent —— `brain_choose_action`：brain 的单步选择评测（B 类，DeepEval）

> 流程位置：**intent.md（本文）** → spec.md → plan.md → PR → production
> 状态：**v1 草案，待确认**
> 起草：2026-10-13
> 关联：`docs/eval/brain-choose-action-spec.md`、`docs/eval/eval-split-intent.md`（三类划分）
> 取代：`tasks-intent.md` 第四节、`tasks-spec.md` 第四、五节中关于 choose 的旧设计（那两处已改为指向本文）

## 一、一句话意图

给定一个**冻结的决策现场**（目标、观测、动作空间、记忆），让文本模型选**一步**动作，用确定性规则判断这个动作是否在**可接受集合**里，并按场合汇总通过率。

## 二、为什么做

1. **choose 是全链路调用最多的模型节点**：task 层每按一键调用一次，但目前只有端到端的整局评测能间接反映它，选错的原因无从定位。
2. **端到端慢、贵、噪声大**：一局几十步，失败原因混在一起；要比较换 prompt、换模型的效果，需要一批固定样本可以反复重测。
3. **它符合 B 类判据**：agent 直接相关、单次输入单次输出、无轨迹，所以走 DeepEval，不走 Inspect。

## 三、测什么、不测什么

**测：** 生产 `Chooser.choose(req)` 的**一次**决策——prompt 渲染 + 模型 + 解析与合法性校验 + 动作规范化。被测的是文本模型（`evals/config.json` 的 `models.text_model`，当前 deepseek-flash）。

**不测：**
- 动作执行后游戏状态是否真的推进（执行验证）：v1 不做，列为后续扩展；
- 多步行为是否走得通：属于 `agent_short_goal_run`；
- 视觉感知、记忆检索、判定器：各有自己的任务。

## 四、核心约定

- **样本 = 一次决策现场。** 冻结的是生产请求信封 `FromHarnessToBrainToolChooseOnceReq`，不是渲染好的 prompt——改了 prompt 要能拿同一批样本重测。
- **真值 = 可接受动作集合，不是唯一答案。** 同一个画面常有几种合理的下一步。每一项要么是"某个按键"（可限连按次数），要么是"某个脚本 + 参数约束"。
- **评分全部确定性，不用 LLM 打分。** 指标：`acceptable`（命中可接受集合）、`parsed`（重试耗尽记失败，这是模型的错）、`legal`（动作在掩码内，出现失败即 bug）。另按场合、按难点标签各出一个分组指标。
- **口径沿用 decode 与第二阶段的 B 类：** 一个现场一个 `LLMTestCase`；无从判的指标跳过；DeepEval 原生输出整体通过率和逐指标汇总；有失败时退出码 1。网络、密钥、网关不通的样本不进分母，运行时列出。
- **可接受集合先由规则算出，再人工全审。** 规则只是预标，人工审过的才进数据集。

## 五、样本从哪来（两路，同一种样本格式）

- **A. 冻结帧。** 从 `evals/dataset/frames/` 的冻结帧出发：用现有的单帧观测装配和动作空间计算，拼出观测与动作空间；人工给每帧配一个目标。这些现场没有记忆，相当于"一局的第一步"。
- **B. 自跑采集。** 从 `.state` 存档起，让 agent 真跑若干步，用评测侧的录制器记下每次决策的信封。这一路才有真实的 `memories` 和 `last_result`，用来覆盖后面两类难点标签。需要本机的模拟器与 ROM，由用户本机运行。

难点标签（字段保留，v1 不设配额）：`read_screen`（答案只在整屏文字里）、`answer_in_memory`（依赖记忆或知识）、`after_failure`（上一步失败后换策略）。A 路天然只有第一类。

## 六、v1 范围

- 只覆盖四类场合：**走路、对话、开始菜单、战斗菜单**，各约 8–10 条，共约 35 条。
- 前三类场合开放按键，可接受集合以按键为主；战斗菜单是"仅开放脚本"的场合，可接受集合以脚本调用为主（2026-10-14 起该场合另开放方向键，用于移动光标，见 spec）。
- 其余场合（商店、背包、PC、队伍、起名、学招等）不在 v1。

## 七、已确认

1. 归 B 类，DeepEval 启动，目录 `evals/brain_choose_action/`。
2. 样本来源两路并用：冻结帧、自跑 `.state` 采集。
3. v1 不做执行验证。
4. v1 只覆盖走路、对话、开始菜单、战斗菜单。
5. 可接受集合：规则预标 + 人工全审；脚本全部人工标。

## 八、非目标

- 不改生产代码、不改 prompt、不改 brain 的任何逻辑。
- 不引入 LLM 判分。
- 不新增别的 brain 节点评测（step_verify、reflect_replan、plan_decompose 另起）。
- 不依赖 `agent_short_goal_run` 的旧存档（它们当前因 `state_schema_hash` 不符被拒载，修复另行安排）。

## 九、成功的样子

- 一条命令：`python -m evals.brain_choose_action`，输出整体通过率，以及 `acceptable`、`parsed`、`legal` 与按场合分组的 `acceptable.<场合>`。
- 换模型或改 prompt 后，用同一批样本直接重测、对比。
- 一次选错能追到具体样本，样本里有当时的完整请求。
