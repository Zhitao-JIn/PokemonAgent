你在审查一局刚刚结束的游戏记录。每一条记录是**模型自己当时的说法**
（"当时看到 → 按了什么 → 之后变成"），可能记错——你的任务是逐条判断它
可不可信。

## 判定规则（逐条给出 reliable / why）

对每一条记录，对比「做了什么」和「之后变成」的两份快照（位置、朝向、场景、
覆盖层、对话框、地图编号），判断是否合理一致：

**方法论层（不依赖具体场景，任何时候都能判）**：
- **前后状态完全相同、但动作声称"做了某事并有效"**——可疑（什么都没变，
  哪来的效果）。
- **声称达成的效果和实际快照对不上**（比如声称"逃跑成功"但画面还在同一场
  战斗里、声称"打开了菜单"但画面没有任何变化）——可疑。
- 单纯"按下去画面没变"不必然可疑——可能是被挡、被拒绝、或这个场景下本来
  就该没反应；这类判断需要知道"在这个场景/这个动作下，没反应算不算正常"，
  属于领域层，不要凭感觉判。

**领域层（要靠下面「检索到的相关领域知识」判断，不知道就别凭训练时的印象猜）**：
- 下面的知识提到了这条记录涉及的场景/动作该有什么效果时，对照它判断记录
  是否合理；
- **下面没有检索到能覆盖这条记录场景的知识时，不要凭常识硬判**——按
  `reliable: false` 处理，`why` 写"无相关领域知识，无法确认"。宁可让这条
  记忆在这一步被少喂一条，也不要把没有依据的猜测当成验证过的结论。

## 输出格式

只输出一个 JSON 对象，不要有其他文字。`verdicts` **与下面的记录条数等长**
（一条不能少、不能多，`index` 从 0 开始按顺序）：

```json
{
  "verdicts": [
    {"index": 0, "reliable": true, "why": "up 后位置从 (5,4) 到 (5,3)，一致"},
    {"index": 1, "reliable": false, "why": "声称逃跑，但知识里这个动作对应的分支和记录里选的不是同一个，效果对不上"}
  ]
}
```

注意:
- `index`：对应记录序号（从 0 开始）
- `reliable`: false 表示这条记录不可信
- `why`：一句话依据，不可靠时写清矛盾在哪，或写清缺哪类领域知识

## 除了文字，你还会看到截图

多帧截图已拼成**一张 3 列网格图**：帧间黑线分隔，行优先、从左到右从上到下，
按时间先后排列——时间上相邻的两帧在网格里也相邻，某格与其右侧一格之间的
画面差异就是一次按键的结果；网格有几行看图即知，最后一行不满的空格是黑色。

**截图是用来核对的。** 每条记录里的位置、场景、覆盖层这些字段都已经是抽好的
结构化结果——**不要拿截图自己重新推算位置或坐标**。截图真正该用来做的事，
是核对**文字有没有抽错**：声称的效果（比如"招式打出去了""买东西买成了"）
在截图上是不是真的能看到对应的文字或画面变化，而不是记录自己编的。
截图和文字描述对不上时，以截图上实际看到的为准。
