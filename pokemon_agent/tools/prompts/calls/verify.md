你在审查一局刚刚结束的游戏记录。每一条是**从机器直接读出的事实**
（"当时看到 → 做了什么 → 之后变成"，或是从这些事实蒸馏出的一条 task 总结）
——记录本身没有真假问题，你的任务是逐条判断：**这条行为/总结符不符合上面
的目标**。符合的标**正样本**，不符合的标**负样本**。

## 判定规则（逐条给出 positive / why）

对每一条记录，对照目标判断它是推进了目标还是偏离了目标。判断要用证据，
证据就在素材里：对比「做了什么」和「之后变成」的两份快照（位置、朝向、
场景、覆盖层、对话框、地图编号），以及下面「检索到的相关领域知识」。

**方法论层（不依赖具体场景，任何时候都能判）**：
- **行为有真实效果、且效果朝着目标推进**——正样本。
- **前后状态完全相同、动作什么都没改变**，或**声称的效果和实际快照对不上**
  （比如声称"逃跑成功"但画面还在同一场战斗里）——这条对目标没有贡献，
  按负样本处理，`why` 写清哪里对不上。
- 单纯"按下去画面没变"不必然是负样本——可能是被挡、被拒绝、或这个场景下
  本来就该没反应；这类判断需要知道"在这个场景/这个动作下，没反应算不算
  正常"，属于领域层，不要凭感觉判。
- **行为真实发生了、但方向与目标无关或背离**（原地绕圈、开无关的菜单、
  走反方向）——负样本，`why` 写清它与目标的差距。

**领域层（要靠下面「检索到的相关领域知识」判断，不知道就别凭训练时的印象猜）**：
- 下面的知识提到了这条记录涉及的场景/动作该有什么效果时，对照它判断这条
  行为是否如预期地服务了目标；
- **下面没有检索到能覆盖这条记录场景的知识时，只按方法论层判**（前后快照有没有
  朝目标的变化），不要凭训练时的印象补领域结论；`why` 里注明"无领域知识，按前后变化判"。
  标注会连同原记录一起交给蒸馏（正负都送），`why` 就是蒸馏读到的理由，所以要写清楚。

## 输出格式

只输出一个 JSON 对象，不要有其他文字。`verdicts` **与下面的记录条数等长**
（一条不能少、不能多，`index` 从 0 开始按顺序）：

```json
{
  "verdicts": [
    {"index": 0, "positive": true, "why": "up 后位置从 (5,4) 到 (5,3)，朝目标方向推进"},
    {"index": 1, "positive": false, "why": "行为真实但方向相反：目标是向北，这步在向南走"}
  ]
}
```

注意:
- `index`：对应记录序号（从 0 开始）
- `positive`: false 表示这是负样本（行为/总结不符合目标）
- `why`：一句话依据，判负样本时写清不符合在哪，或写清缺哪类领域知识

## 除了文字，你还会看到截图

多帧截图已拼成**一张 3 列网格图**：帧间黑线分隔，行优先、从左到右从上到下，
按时间先后排列——时间上相邻的两帧在网格里也相邻，某格与其右侧一格之间的
画面差异就是一次按键的结果；网格有几行看图即知，最后一行不满的空格是黑色。

**截图是用来核对的。** 每条记录里的位置、场景、覆盖层这些字段都已经是抽好的
结构化结果——**不要拿截图自己重新推算位置或坐标**。截图真正该用来做的事，
是核对**文字有没有抽错**：声称的效果（比如"招式打出去了""买东西买成了"）
在截图上是不是真的能看到对应的文字或画面变化，而不是记录自己编的。
截图和文字描述对不上时，以截图上实际看到的为准。
