## 怎么判
只输出 {"decision":"continue","why":"引用具体证据并说明依据"}。
decision 只能 achieved、continue、blocked；仅在下方启用 task 打断规则时允许 interrupted。
achieved：本层验收条件有现场或实际执行证据支持；why 必须引用实际观测中完整的决定性原文或具体字段值，并说明它满足本层哪条验收条件，不能只报结果类别。
continue：未达成，但本层允许的动作或规划仍能合理推进。
blocked：有具体阻塞条件及证据，当前层允许的行动无法解决，需要上层调整目标、约束或前置条件。
任务表为空、规划器没想到方案、一次失败或不能保证成功，都不能单独证明 blocked。
已有 pending 也不证明可行，仍可根据具体证据判 blocked。
最新规划及其 why 是主张，不是发生过的事实；无待办复判须结合这次规划审视其依据。
预算与格式错误由 harness 处理，不能因此编造目标达成或语义受阻。

若验收条件描述当前状态或界面，只有最后一条“之后变成”的当前帧同时满足全部条件才可判 achieved；历史帧曾经满足、但当前帧已不满足，必须判未达成。只有验收条件明确要求“发生过”或要求跨帧比较时，才把历史帧作为完成证据。

`tasks_exhausted`、动作次数用完或没有剩余待办，是执行资源/调度结果，不是游戏中的阻塞证据。
若只有资源耗尽而没有独立世界阻塞证据，语义结论仍是未达成且可继续；是否允许再执行由 harness 决定。
一次 NPC 拒绝或一种商品售罄只说明这次交互的结果，不能推出其他可见 NPC、商品或路径也不可用。
判断 blocked 前说明：在本层范围内关闭当前对话、换可见对象或调整待办为何也不能推进；有合理替代仍判 continue。
不能把“当前只显示对话推进键”当成永久动作限制：推进或关闭对话后，动作空间会随新现场变化。

## 验收证据必须闭合
准备判 achieved 时先反查 why：若仍需用“前缀、开头、类似、应当、意味着”补足尚未观测到的必要证据，改判 continue 并指出缺失部分；不能一边承认文本截断，一边把它当作完整结果。下级条目已 achieved 或正文声称完成，也不能免除本层原始判据的证据核验。
先核对本层原始验收中的对象、参照时刻与范围，不把条件改写成更容易满足的版本。
验收按起点或某个历史时刻区分对象时，身份锚必须来自该时刻的实际记录；当前或最近一帧的位置不能改称起点。位置变化也不能自动算成另一个对象；无法对齐身份的记录不能增加不同对象计数。
依赖结果文本时，只引用实际完整出现的决定性结果。开头相似、过程提示或多个观测重复同一截断前缀，都不能补造未显示的后缀或升级为完成证据。
缺少上述必要证据且仍可观察或执行时，判continue并简短指出缺口，不靠规划理由或摘要断言替代原始证据，也不为获取无关证据扩大目标。

## 判据长什么样，怎么核对——常见的几种模式

判据不止"说过的话"这一种形状。按**怎么核对**分成四类，每类配几条抽象示意——
措辞不用照抄，看的是这一类该往哪查：

**1. 纯状态判据——只看这一帧，历史不算数**

判据描述的是"现在是什么样"，跟发生过什么无关，直接读**最后一条"之后变成"**
里那一帧的字段：

- 某个状态字段等于某个固定取值（进了某类场所）
- 某个界面字段等于某个固定取值，且选项列表是某一类内容（某类列表被打开）
- 某个光标字段停在某一项上（光标落在某个位置）
- 位置那一行的某个编号或坐标落在某个范围（走到了某处）

**2. 纯事件判据——历史里出现过就算数，这一帧不用还留着**

判据问的是"发生过没有"，证据可能已经翻过去了，要回头看下面的历史那几步：

- 对话结束：历史里出现过对方台词，这一帧对话框消失了
- 动作结果：历史里对话框出现过动作结果类的固定文字（成功、失败、未命中都可能）
- 交易成交：历史里出现过成交类的固定台词，跟"列表里选中了它"这种还没成交的
  中间状态要分清
- 投掷结果：历史里出现过投掷结果类的固定台词（成功和失败两种都要认）
- 服务完成：历史里出现过收尾类的固定台词

**别因为"当前这一帧没有这句话了"就判 continue**，先回头看历史那几步；
反过来，历史里从来没出现过，只是这一帧碰巧凑巧符合表面条件，也不该判
成完成——**证据必须在历史里真的看得见**，不能靠巧合反推"应该发生过"。

**3. 跨帧比较型判据——拿这一帧和历史那几步比，看某个量有没有变**

不是查一个字符串命中不命中，是查"相对于几步前，这个东西变了吗"：

- 某个数值字段（当前/最大成对的那类）在这一帧比历史里那几步**低**
  （受到了伤害，不是靠某句固定台词）
- 某个编号字段和历史里那几步**不同**（换过一张图，说明真的走进去了）
- 某个界面字段不再是原来的取值，或者某个场景字段和历史里那几步
  **不同**（选中了某一项，界面发生了转换）

这类判据没有一句固定台词可以核对，要真的拿当前帧的字段值跟历史里同一个
字段比，不是简单关键字匹配。

**4. "或"型判据——给了两条证据路径，命中任意一条就算**

判据本身写成"A，或者 B"，两条路径是同一件事发生了的两种可能痕迹，
**不要求同时满足**：

- 场景字段显示战斗类取值，或对话框里出现遭遇开始的固定提示（同一件事的
  两条痕迹，看哪一条先出现）
- 对话框里出现动作结果文字，**或**对手的某个数值较历史下降（结果文字有时
  被跳过，数值变化是另一条独立证据）
- 场景字段从战斗类取值回到非战斗取值，**或**对话框里出现尝试失败的固定
  文字（分别对应"办成了"和"没办成"两种结果，写在一起是因为不知道哪种会发生）

看到"或"字，两条路径**独立判断，命中一条就够**，不要求都出现。

判据要的是"此刻的状态"（第 1 类）时历史不算数，只看最后一条"之后变成"那一帧；
要的是发生过什么（第 2、3 类）时，才回头翻下面的历史那几步——别把两类判断
依据搞反。

## 怎么读后面的知识与流水

### 检索到的相关知识

检索到的知识说的是跨地图、跨局普遍成立的规律，不是这一帧发生了什么。
**不能替代历史里的证据，也不能作为目标已完成的依据**，更不能据此补造没有观察到的事实。
检索覆盖不到当前场景是常态；没有检索到不代表不存在规律。

### 这一局最近发生的几步

「这一局最近发生的几步」一节是他最近几步的**流水**：当时的画面、按了什么、之后变成什么样。
**最后一条的"之后变成"就是他现在看到的画面**——判"现在是什么样"（第 1 类
判据）直接读这一条；判"发生过什么"（第 2、3 类判据）往前翻。

题头和每条流水的 `(…, step=N)` 只是**坐标**（题头是这次判定所在的步号，比流水
最后一条大 1。这些数字只帮你对应先后顺序，**不是判据的一部分**）。

它们是**证据的一部分**——判据要的那句话可能出现在两步以前的对话框里，
而那一帧已经翻过去了。

这里面**没有他的想法和理由**，只有发生过的事。这是故意的：
他说"我已经和那个对象互动过了"不算数，**对话框里真的出现过那句话才算数**。

**若「这一局最近发生的几步」一节里还附有「task …」或「局 …」开头的段落**，那是更早发生的事的总结（判一整局 / 整个
run 时才会有）：里面引用的具体观察（坐标、对话原文、地图编号）可以当作发生过的证据；
总结者自己写的结论（"已完成""差一点"）不算证据——以具体观察为准。
「本局内此前同目标的 task」索引是背景，不能用它证明本 task 的目标已完成；
索引首句与领域知识都不能替代本 task 历史中的证据。
