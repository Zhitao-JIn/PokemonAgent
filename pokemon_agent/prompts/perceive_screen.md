你在读一张《宝可梦 红版》（Game Boy，160×144 像素）的游戏画面。
把它解析成结构化状态。**只输出一个 JSON 对象，不要有任何其他文字。**

画面上叠了一层红色网格，把屏幕分成 **10 列 × 9 行**共 90 个格子。
列号 `0`–`9` 标在画面上边框，行号 `0`–`8` 标在左边框。
下文用 `(列, 行)` 指代格子，例如 `(4,3)` 是第 4 列第 3 行。

**主角永远站在 `(4,4)`。** 这是固定的，镜头始终跟着他——不要去画面里找他。

## 一、判定界面类型（两个独立维度）

界面类型由两个维度共同描述，**不是一个枚举**。

`scene` —— 你处在什么场合，决定要读哪些字段：

- `field` 野外：城镇、道路，角色可自由走动，画面是俯视地图
- `indoor` 室内：研究所、民宅、道馆内部，同为俯视地图但有墙壁和地板纹理
- `battle` 战斗：**必须同时有两只宝可梦和两个状态框**——上方是对手，
  下方是我方（背影）。少了任何一边就不是战斗
- `menu` 系统菜单。以下这些都是 `menu`，**不是 `battle`**：
    - **精灵状态页**：一只宝可梦立绘 + `ATTACK` `DEFENSE` `SPEED` `SPECIAL`
      属性表 + `No.xxx` + `TYPE1/TYPE2`
    - **精灵列表**：一到六条「名字 + 等级 + HP 条」横排，底部有提示文字
    - **背包**：道具名与数量的列表
    - **START 菜单**：`POKéDEX` `POKéMON` `ITEM` `SAVE` `OPTION` 这类条目
  这些画面上都有 HP 条和等级，**但那是在展示信息，不是在打架**。
- `shop` 商店：**买卖菜单**——商品列表 + 价格 + 所持金钱。
  注意：站在地图上看到一栋写着 `POKé MART` 的**建筑外观**是 `field`，不是 `shop`；
  只有真正进入买卖界面才算
- `transition` 过场：黑屏、白闪、进出门的切换画面，没有稳定内容

`overlay` —— 屏幕上盖着什么等你操作，决定可以按什么键：

- `none` 没有弹出层，直接操作角色
- `dialog` 对话框：画面底部有一个方框，里面是一段等待推进的文本，**没有可选项**
- `choice` 选择框：有一组并列的选项，且有一个光标（`▶` 或高亮）指向其中一项

**注意 `dialog` 和 `choice` 都可能出现在任何 `scene` 上。** 战斗中有对话框、
室内也有对话框；它们的 `scene` 不同但 `overlay` 相同。不要把"对话框"当成一种场合。

## 二、Gen1 战斗界面的布局（`scene=battle` 时必读）

这一节是**硬规则，不要靠画面猜**：

- **左上角**的状态框属于**对手**。里面是对手的名字、等级、HP 条。
- **右下角**的状态框属于**我方**。里面是我方的名字、等级、HP 条，以及 `当前/最大` 形式的 HP 数字。
- 画面**上方**的宝可梦是对手，**下方（背影）**的是我方。
- 底部若出现 `TYPE/xxx` 和一组 `nn/nn`，那是**当前高亮技能的属性和 PP**，
  **不是任何一方的 HP**。不要把 PP 填进 HP 字段。

## 三、野外与室内：读地形矩阵（`scene` 是 `field` 或 `indoor` 时必读）

**画面上方是北。** 逐格判断这 90 个格子里**各是什么地形**，填进 `walk_map`：
9 个字符串，每个 10 个字符，从第 0 行到第 8 行。

**你的任务是认出这格是什么东西，不是判断能不能走过去。**
下面的说明是给读你输出的那一方看的，你只管照实报符号。

- `.` 普通地面 —— 能走
- `G` 草丛 —— 能走，走进去会遇野生宝可梦
- `D` 门/入口/楼梯 —— 能进，通往另一张地图
- `L` 台阶断崖 —— 只能从上往下跳，反方向过不去
- `N` 人 —— 走不过去；面朝它按 A 可以对话
- `S` 招牌或可调查物 —— 走不过去；面朝它按 A 可以调查
- `W` 水面 —— 走不过去，学会冲浪之前过不去
- `#` 墙/树/建筑/家具 —— 走不过去
- `?` 看不清 —— 这一帧没读出来。**不代表不能走**，想去就单独走一步试
- `@` 主角自己 —— **必须且只能出现在 (4,4)**

### 第一步：写 `overview`（**必须最先写**）

用一两句话说清整幅画面的布局，例如：

    左上角一片草丛，中上方一栋房子、门开在正下方；画面中间横着一排断崖，
    只在主角正下方有个缺口；下半部是空地，左侧立着一块招牌。

**先说整体，再填格子。** 这个顺序不是排版，是方法：先做一次全局判断，
后面那 90 次逐格判断就有了约束；反过来先填格子再总结，总结只会复述已经填错的东西。

写清楚三样：**大块的东西在哪**（房子、草丛、水面在画面的哪个方位）、
**有没有横贯的边界**（断崖、栅栏、墙）、**有没有人或可调查的东西**。

### 先认物体，再填格子

**不要一格一格地独立猜。** 画面不是 90 个互不相干的格子，是几个物体光栅化的结果。
先看出画面里有哪几样东西、各占哪块矩形，再把它们填进网格——这样每一格都有约束，
而不是 90 次孤立的判断。

物体各自长什么样：

- **房子**：一整块矩形，上半是屋顶（有瓦片纹理或斜纹），下半是墙面，通常至少 3×3。
  **门一定在房子的最下面一排，而且门的正上方必须是这栋房子的墙或屋顶。**
  一个 `D` 上面如果是草地或空地，那它就不是门——多半是块深色地面或阴影。
- **草丛**：成片出现，有明显的短竖纹。**孤零零一格的草丛很少见**，
  看到单独一格就要怀疑是不是把普通地面的花纹当成草了。
- **断崖（`L`）**：横向连成一条，上下两侧地面高度不同。**不会只有一格**。
- **水面（`W`）**：大片连通，有横向波纹。
- **人（`N`）**：一个人形贴图占一格，有头有身体，通常朝某个方向。
  **人站在能走的地上**，所以它周围应该有可走的格子；
  嵌在一整块墙里的"人"多半是墙上的花纹或窗户。
- **招牌（`S`）**：一小块方形立牌，通常紧挨着路边，孤立出现。

### 填完之后自查这四条

不满足就回去改，改不动就把那几格写成 `?`：

1. 每个 `D` 的正上方是不是 `#`？不是就不是门。
2. 每个 `N` 的四周至少有一格能走吗？没有就不是人。
3. `G` / `W` / `L` 是不是成片或成条？孤立单格要重新看。
4. `@` 在 `(4,4)` 吗？不在说明行列数错了，重数。

**自查不是让你把不确定的东西改成确定的，是让你把矛盾的地方改成 `?`。**

三条要点：

- **门（`D`）看上去就是建筑墙面上的一块深色矩形**，和墙很像。认出来就标 `D`，
  不要因为"它看着像墙"标成 `#`——那正是这套符号要解决的问题。
  室内的楼梯、地毯样的出口也是 `D`。
- **看不清就写 `?`，不要猜。** 被对话框遮住、在画面边缘只露一半、太暗分不清，
  统统写 `?`。写 `?` 没有任何代价，猜错才有。
  底部有对话框时，被它盖住的那几行**整行都写 `?`**。
- **`@` 是一道自检。** 如果你数出来的 `@` 不在第 4 列第 4 行，说明行列数错了，
  重新数一遍再输出。

## 三之二、地标

`landmarks` 是一个字符串数组，每条形如 `<是什么> (列,行)`：

    ["宝可梦中心门 (4,3)", "招牌 (2,7)", "老爷爷 (7,4)"]

**必须带坐标。** 「北边有一栋建筑」这种没有坐标的描述已经实测过，
它对导航没有任何用处，只会变成噪声。

只写你确实看得出是什么的东西：门、招牌、NPC、可调查的物件、楼梯、传送点。
一整片树林、一整面墙不用写——那些矩阵里已经有了。

看不出有什么值得记的就给空数组。

## 四、按 scene 填 fields

判定出 `scene` 后，填它对应的那一组字段，放进 `fields`：

- `field` → 不需要任何字段，`fields` 留空对象
- `indoor` → 不需要任何字段，`fields` 留空对象
- `battle` → `my_name`, `my_level`, `my_hp`, `foe_name`, `foe_level`, `foe_hp`
- `menu` → `title`
- `shop` → `money`, `items`
- `transition` → 不需要任何字段，`fields` 留空对象

## 五、抄写规则

- **所有名字原样抄英文，不要翻译成中文，不要用你记忆里的宝可梦名字纠正它。**
  玩家可以给宝可梦起任意昵称，画面上写什么就是什么。
- **不要写画面上看不到的东西。** 尤其：**不要判断这是哪个城镇、哪条道路**——
  野外画面不显示地名，任何地名都只能是你从游戏知识里猜的。
  你的任务是报告这一帧里有什么，不是回忆这个游戏该长什么样。
- 数字原样抄，不要计算、不要补全。
- `fields` 的值**一律写成字符串**：`"my_level": "5"` 而不是 `5`。多个值用 `, ` 连接。
- `scene` 是 `battle` / `menu` / `shop` / `transition` 时，
  `walk_map` 给**空数组**，`landmarks` 也给空数组——那些画面没有可走的地图。
- **读不出来的字段直接不要放进 `fields`。** 不要填空字符串、`unknown`、`?` 或任何占位值。
  漏填是可以统计的，猜错是无法察觉的。
- `dialog_text` 抄对话框里的全部文本，换行用空格连接。没有对话框就留空字符串。
- `options` 按屏幕上从上到下的顺序列出选项原文。没有选择框就留空数组。
- `cursor` 是光标指向第几项，从 0 开始。看不出光标位置就填 `null`。
- `scene=menu` 时 `title` 填这个菜单是什么（如 `状态`、`背包`、`精灵列表`、`主菜单`）；
  菜单里的条目放 `options`，**不要**把状态页上的属性数值硬塞进 `fields`——
  那部分本阶段不提取。

## 六、每一类的输出样例

下面每一类各给一份完整样例。**照着当前画面属于的那一类的形状输出，字段顺序也照抄**——`overview` 在前不是排版偏好，是让你先想后填。

### `field`

**`overview` 写在最前面**，它是后面一切的约束。宝可梦中心的门是 `D`，正上方是 `#`（房子）——符合自查第 1 条。

```json
{
  "scene": "field",
  "overlay": "none",
  "overview": "左上角一片草丛，中上方一栋房子、门开在正下方；画面中间横着一排断崖，只在主角正下方有个缺口；下半部是空地，左侧立着一块招牌。",
  "dialog_text": "",
  "options": [],
  "cursor": null,
  "fields": {},
  "walk_map": [
    "GG####....",
    "GG####....",
    "GG####....",
    "GG##D#....",
    "....@.....",
    "LLLL.LLLLL",
    "..........",
    "..S.......",
    ".........."
  ],
  "landmarks": [
    "宝可梦中心 (4,3)",
    "路线指示牌 (2,7)"
  ]
}
```

### `indoor`

**被对话框盖住的三行整行写 `?`**，`overview` 里也明说了这一点。大木博士是 `N`，四周有可走的格子。

```json
{
  "scene": "indoor",
  "overlay": "dialog",
  "overview": "一间四面是墙的房间，中间一组柜子，柜子前站着一个人；右下方有一处出口。画面下方三行被对话框盖住，看不到地面。",
  "dialog_text": "OAK: Hello there! Welcome to the world of POKéMON!",
  "options": [],
  "cursor": null,
  "fields": {},
  "walk_map": [
    "##########",
    "#........#",
    "#..####..#",
    "#..#N##..#",
    "#...@....#",
    "#....D...#",
    "??????????",
    "??????????",
    "??????????"
  ],
  "landmarks": [
    "大木博士 (4,3)",
    "出口 (5,5)"
  ]
}
```

### `battle`

**`walk_map` 和 `landmarks` 都是空数组**：战斗画面没有地图。`overview` 照样要写。

```json
{
  "scene": "battle",
  "overlay": "choice",
  "overview": "战斗画面：右上是对手，左下是我方背影，右下角是四选项指令框。",
  "dialog_text": "",
  "options": [
    "FIGHT",
    "PKMN",
    "ITEM",
    "RUN"
  ],
  "cursor": 0,
  "fields": {
    "foe_name": "CHARMANDER",
    "foe_level": "5",
    "foe_hp": "18/18",
    "my_name": "AL",
    "my_level": "5",
    "my_hp": "19/19"
  },
  "walk_map": [],
  "landmarks": []
}
```

### `menu`

菜单条目放 `options`，`cursor` 是光标停在第几项（0 起）。

```json
{
  "scene": "menu",
  "overlay": "choice",
  "overview": "画面右侧弹出一列主菜单条目，光标停在第二项。",
  "dialog_text": "",
  "options": [
    "POKéDEX",
    "POKéMON",
    "ITEM",
    "RED",
    "SAVE",
    "OPTION",
    "EXIT"
  ],
  "cursor": 1,
  "fields": {
    "title": "主菜单"
  },
  "walk_map": [],
  "landmarks": []
}
```

### `shop`

商品列表同时出现在 `options` 和 `fields.items` 里，前者给按键用，后者给统计用。

```json
{
  "scene": "shop",
  "overlay": "choice",
  "overview": "商店买卖界面：上方是所持金钱，下方是商品与价格的列表。",
  "dialog_text": "",
  "options": [
    "POKé BALL",
    "POTION",
    "ANTIDOTE",
    "CANCEL"
  ],
  "cursor": 0,
  "fields": {
    "money": "3000",
    "items": "POKé BALL, POTION, ANTIDOTE"
  },
  "walk_map": [],
  "landmarks": []
}
```

### `transition`

过场画面**除了 `overview` 什么都不填**。没有内容就是没有内容，硬填就是编。

```json
{
  "scene": "transition",
  "overlay": "none",
  "overview": "画面正在切换，全黑，没有可辨认的内容。",
  "dialog_text": "",
  "options": [],
  "cursor": null,
  "fields": {},
  "walk_map": [],
  "landmarks": []
}
```

再说一次：**只输出一个 JSON 对象，前后不要有解释、不要有 ```json 包裹。**
