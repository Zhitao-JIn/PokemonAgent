## 输出格式

只输出一个 JSON 对象，不要有其他文字。**按 `intent` 决定填哪些字段**：

按键（推进游戏）：
```json
{"thought": "完整推理", "rationale": ["论据一"],
 "intent": "press", "action": "up", "args": {"times": "1"}}
```

拆一个子目标压进栈（不推进游戏）：
```json
{"thought": "完整推理", "rationale": ["论据一"],
 "intent": "push_goal", "goal": "进到 x=13 y=5 那扇门里",
 "criteria": "map_id 不再是 0，scene 变成室内"}
```

细看一个具体的地方（不推进游戏）：
```json
{"thought": "完整推理", "rationale": ["论据一"],
 "intent": "inspect", "focus": "(7,7) 那格到底是门还是窗户"}
```

## 各字段的要求

- **thought**：完整推理，想多长都可以。它只用于记录，不会进入以后的决策。
- **rationale**：1-$max_rationale 条，写清楚「为什么这个动作在当前状态下成立」的依据。
  不要复述动作本身（"所以该往前走"不是论据）。
  **这些会被存进记忆，将来在相似状态下取回**——所以要写成以后还能判断真假的样子，
  例如"地上有药水而我手上没有"，而不是"我觉得这样比较好"。
- **args.times**（press）：这个键连按几次，1 到 8。**press 时这个字段必须出现**，默认 `"1"`。
  连按期间看不到中间画面，所以只在确信不会中途变化时调大：
  沿直线走几格、连按 A 推进整段对话。
- **goal**（push_goal）：**里程碑，不是路径点。**
  达成的那一帧画面要**明显不一样**：进了某扇门、和某个人说上话、换了张地图。
  "往右走两格"不是子目标，那是一个按键——直接按就行。
  拆成目标是白烧一步，而且它会一直挂在栈上，**每一步都要为它多花一次判定调用**。
- **criteria**（push_goal）：**必须能只看一帧画面就判断真假**。
  会有另一个人拿着这句话逐帧检查，他看不到你的推理，也**看不到 `walk_map` 和
  `landmarks`**——他手上只有 `where` / `map_id` / `scene` / 对话框文字 / `overview`。
  判据只能引用这几样。
  **位置一律写成 `x=.. y=..`，不要写成 `(6,4)` 这种括号对，也不要提 `walk_map`。**
  `walk_map` 的行列号已经就是全局坐标了，照抄那两个数即可；
  而判定的人看不到那张图，判据里提它等于没说。
  "走得更近了"不行（没有判据），"map_id 变成 37" 可以。
- **focus**（inspect）：一个**具体的问题**，不是"再看看"。
  同一帧的整体描述你已经拿到了，再要一遍不会有任何新内容；
  只有问一个新问题（哪一格、什么东西、什么字）才会得到新答案。
