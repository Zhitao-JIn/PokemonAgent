## 怎么读 walk_map
已知事实里的 `walk_map` 是一张 10 列 x 9 行的地图，**它来自模拟器内存，不是看出来的，100% 准确**：
$terrain_legend

## 只有一套坐标
图上的行号 `y=..`，和 `where` / `landmarks` / `known_objects` 里的 `x= y=`
**是同一套数**，不需要任何换算，也没有第二套坐标。

$sample_map

`@` 就是你，它那一格的坐标 `where` 那一行写着。
**y 向下增大，x 向右增大。**

## 图上没有列号，别在图上找东西
一列只有一个字符宽，两三位数的 x 写不进去，所以**只给了行号**。
这不影响你做任何事，因为**你本来就不该在图上数格子找东西**：
- 门 / 招牌 / 人在哪 —— `landmarks` 和 `known_objects` 里写着确切坐标。
- 四个方向各是什么 —— `neighbors` 已经算好了，那是决定这一步能不能动的四格。

**这张图剩下的用处是看形状**：朝那个方向走得通吗、哪边是死路、
绕过去要从哪边绕。看形状不需要列号，从 `@` 往那个方向看过去就行。

`walk_map` **每一行恰好 10 个字符，没有空格**——`##...S#D##` 里 `##...`
是**三个点**。**图和 `landmarks` 对不上时是你数错了，不是数据错了**：
两者都来自模拟器内存，同一帧读出来的，不可能互相矛盾。
不要花篇幅论证哪一边可信，以 `landmarks` 为准。

## 站在 `D` 上的时候，朝地图外面那个方向按
**室内的出口就是这么用的**：门格贴着地图边界，`neighbors` 会告诉你那个方向是
`#`，但**按下去就出去了**。`#` 说的是「走不过去」，不是「按了没用」——
门格上的那一下不是走路，是开门。

所以站在 `D` 上没换图时，**先把四个方向里那个朝向地图边界的试一遍**，
而不是换一扇门。两扇门挨着的时候尤其要注意：
从这扇门走到那扇门，走的还是屋里，`map_id` 一个数都没变。

## 地标没有名字，`known_objects` 才有
`landmarks` 只说「这里有一扇门 / 一块招牌 / 一个人」和它在哪，**不说那是谁家、招牌上写什么**——那些字在这个画面里根本没有渲染，写出来只能是编的。

已知事实里的 `known_objects` 是**这张地图上你见过的每一个**门/招牌/人的档案，坐标和 `landmarks` 是同一套，**直接对得上，不需要换算**。一条档案是一个抬头加几条缩进的明细，条与条之间空一行：

```
全局坐标 地图0 x=13 y=5 的「门」（见过 7 次，互动 1 次）
  **已经走通**：通往地图39

全局坐标 地图0 x=11 y=5 的「招牌」（见过 7 次，互动 1 次）
  说过：PALLET TOWN. Shades of your journey await!

全局坐标 地图0 x=5 y=5 的「门」（见过 7 次，互动 0 次）
  **还没互动过**
```

**「还没互动过」是你的待办清单。** 想找的东西不在已知的那几条里，就去试没试过的那几个——而不是对着试过的再按一遍。
门的「通往地图N」是**你自己走进去换来的**，没走过就没有。

## 门的「试过」怎么读
**站在门那一格上**按四个方向之一，或者**从旁边推过去**（走到它相邻的一格，再朝它按）——一共 8 种碰法。**门只有一种成功：`map_id` 变了**，人走到了门那一格上不算，两扇门挨着的时候尤其要注意，从这扇门走到那扇门，走的还是屋里。

## 明细里写的是「站在哪一格、按哪个键 → 结果」

```
全局坐标 地图37 x=2 y=7 的「门」（见过 3 次，互动 1 次）
  **已经走通**：通往地图0
  站在 x=2 y=8 按 up → 进入新地图0

全局坐标 地图0 x=5 y=5 的「门」（见过 7 次，互动 1 次）
  **还没打开过**（还剩 7 种碰法没试）
  站在 x=5 y=6 按 up → 无效果
```

第一种（写着「已经走通」）**照着做就行**：走到明细里那一格，按写着的那个键。

第二种里「站在 x=5 y=6 按 up」的坐标是**你按键时站的那一格**，不是门的坐标。
把它和抬头里的门坐标一比就知道是站在门上按、还是从旁边推：重合就是站上面按，
不重合就是从那一格朝门的方向推。**这几条别再试第二遍**，
「还剩 N 种」是从 8 种里减掉已经试过的——**这个数大于 0 就说明还有别的可试，
不要换一扇门**。写着「8 种碰法全试过了」的那扇门就是打不开（剧情没到，或者它是装饰）。

人和招牌不用这一套：它们只有「面朝它按 `a`」一种碰法，说过的话直接写在条目里。

## 障碍物不等于 NPC 不可对话
`N` 人格子本身不可走，但 `#` **只说明不能移动穿过或站上该格，不说明不能和另一侧的人互动**。
游戏里的 NPC 交互可能隔着柜台、货架或墙发生；因此不能因为 NPC 与主角之间存在 `#`，
就把这个人判定为“不可对话”。以 `landmarks` / `known_objects` 识别出的 NPC 为候选目标，
结合主角当前朝向、画面中的人物位置和此前互动结果，尝试一次 `a` 验证。

规划 NPC 交互时：
1. 从 `landmarks` 读取 NPC 的精确坐标，不要只凭 `walk_map` 判断它能否接近。
2. `#` 只用于规划移动绕路；不要把“无法走到 NPC 相邻格”当成交互失败的证明。
3. 如果画面能明确看到 NPC、目标在主角面朝方向，且 `overlay=none`，优先按一次 `a`，即使中间有 `#`。
4. 只有在按 `a` 后确认没有反应，才换朝向、换候选 NPC 或继续移动；不要在尚未验证时放弃目标。
5. 如果按 `a` 只是重复同一句固定台词，那它多半不是当前目标的交互对象——换一个，别无限连按。

例如 `walk_map` 中主角和 `N` 之间夹着 `#` 时，仍可能是柜台式交互：主角不能穿过 `#`，
但可以面朝该 NPC 按 `a`。

`walk_map` 和 `landmarks` 都来自模拟器内存，**都不会错**。地图每一帧重新给出，不存在跨步骤的额度或余量。
