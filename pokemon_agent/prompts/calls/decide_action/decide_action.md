你在玩神奇宝贝。按 ReAct 的方式思考，选出**这一步要按的按键链**。

一步交出的不是一个键，而是一条链（`sequence`）：链里的按键会连着按完，中间不重新观察，按完之后你才会看到新画面。所以「这一步做多少」由你决定——把能一次走完的走完，遇到转弯或预期会有事发生就在那里收住。

## 停滞时要换打法

如果最近几步你交出的是**相同或相似的动作**，而画面关键状态（位置、场景、对话框、光标）没有任何变化，说明这条路走不通。**必须换一种尝试方向**——换一个按键、换一个位置、或转向目标的另一条路径；把同一个动作再交一遍，只会得到同一个结果。这一条是软约束：连续原地打转会被强制结束本局，那比换错方向代价更大。

## 输出格式

只输出一个 JSON 对象，不要有其他文字：

```json
{"thought": "完整推理", "rationale": ["论据一"],
 "sequence": [{"action": "up", "times": 4}, {"action": "down", "times": 4}]}
```

## 各字段的要求

- **thought**：完整推理，**最长约 1024 token**。它只用于记录，不会进入以后的决策——写长不会加分，压缩它压的是废话，不是思考。
- **rationale**：1-$max_rationale 条。**先满足下面两条硬规则，再谈写法：**
  1. **只写「现在已经看到的」，不写「这么走了之后会看到什么」，也不写「这就算完成了」。**
     `walk_map`/`landmarks`/`known_objects` 只覆盖这一帧屏幕内的格子；走到屏幕边缘、
     或者知道「这个方向最终能走到某个地方」，都不等于知道**下一格**是什么——那一格还没
     加载出来，`neighbors` 也还没显示它。凡是断言某格是门/是某个 landmark、或者断言
     目标判据已经满足，**必须写得出具体依据**：`walk_map` 里第几行出现的 `D`、或者
     `landmarks`/`known_objects` 里哪一条的坐标——**写不出坐标就是在猜，不能写进
     rationale**。判据满不满足由独立的 judge 判断，这里只写「为什么选这个动作」，
     不许出现「满足……判据」「已完成……」这类结论性说法。
  2. **这条记录会原样进入记忆（`StepMemory.rationale`），写入后不会再被核对**——
     以后取回时会被直接当成已验证的事实用掉，所以现在写的时候就要对得起这个分量：
     宁可写得保守、留白，也不要把还没发生的事写成已经发生。
  不要复述动作本身（「所以该往前走」不是论据），要写成以后还能判断真假的样子——
  例如「地上有药水而我手上没有」，而不是「我觉得这样比较好」。
  3. **每一条必须写成「依据 → 结论」的形状，两半都要有，缺一半不能写进 rationale**：
     依据是「已知事实」里能指出处的具体内容（字段名、坐标、`walk_map` 第几行、
     `known_objects`/`landmarks` 哪一条），结论是这依据支持你选这个动作。只有
     结论没有依据（「这样比较好」）不合格；只有依据没有结论（复述一遍已知事实，
     不说它支持了什么）同样不合格——那是在凑数，不是论据。
     - ✅ 「`known_objects` 第 2 条记着「已互动 3 次、结果都是无效果」，所以换一个
       目标而不是再按一次」——依据（互动记录）→ 结论（换目标）都在。
     - ❌ 「这个方向最终能走到宝可梦中心，所以往这走」——这是训练时/检索到的
       跨地图知识当成了这一帧的证据，真正的问题正是这一条：0903 一次事故里，
       模型把"知识说这个方向最终能到宝可梦中心"（跨地图关系，长期为真）和
       "屏幕边缘的下一格就是门"（这一帧根本没加载出来）混成一件事，写进
       rationale 之后再也没有被核对过，执行后发现四邻全是 `.`，没有任何门的
       证据。**任何跨地图/跨局的知识只能用来指导"该怎么做"，不能替代"已知
       事实"里这一帧真正看到的依据**——写门/landmark 相关的结论，依据必须来自
       `walk_map`/`known_objects` 里这一帧当场读出来的坐标，不能来自「检索到的
       相关知识」或「跨局摘要记忆」那两节。
- **sequence**：必须是非空数组，每段写 `{"action": 键, "times": N}`，N 为 1 到 8。
  - 长度为 1：任意一个当前可用按键，例如 `{"sequence": [{"action": "a", "times": 1}]}`。
  - 长度大于 1：前面每一段必须是方向键 `up`、`down`、`left` 或 `right`（可以拐弯，也可以原路折回，例如 `up×4` 接 `down×4` 在同一段路上来回走），
    **最后一段允许是 `a`**（最多一个，且只能在末尾），用来「走过去再按一下」，
    例如 `[{"action": "up", "times": 2}, {"action": "a", "times": 1}]`。
  - **`a` 永远是 1**（写大了也会被改成 1）：对话一句一句出来，连按会把中间那几句
    整个吃掉，而判据要的那句话往往就在中间。
  怎么数 `times`、什么时候该把链缩短，见可用按键那一节末尾的说明。

$map_guide

`known_objects` 里每条档案的抬头写着「互动 N 次」，明细里写着**站在哪一格、按了哪个键、
结果是什么**。这是**已经发生过的事实**，不是参考意见——下面三条是硬规则：

- **同一格、同一个键、结果是「无效果」，就不要再按第二次。**
  同样的姿势碰同一个东西只会得到同样的结果。
  想再碰它，必须换姿势：换一格站、换一个朝向，或者换一个对象。
- 某个对象上「无效果」的记录已经有 **2 条或更多**（或抬头的互动次数明显大于它说过的话），
  说明**你对它的判断本身是错的**——先怀疑「这是不是我要找的那个东西」，
  而不是怀疑「是不是按得不够多」。这时 `thought` 里必须先写一句
  「已失败 N 次，所以原来的假设 X 不成立」，再写新的做法。
- 「它就在正前方、朝向也对、中间没有障碍」是**能不能按**的理由，
  不是**按了会有用**的理由。当这套理由已经被记录里的失败推翻过一次，就不能再拿它当论据。

`rationale` 里不许出现「这次应该会成功」这类没有新证据的说法：
和上一次相比，**必须有一样东西变了**（站的位置、朝向、按的键、或者对象），
说不出变了什么，就说明这一步是在重复一个已知无效的动作。

## 检索到的相关知识（怎么信）

按当前场景/目标从知识库（`semantic/knowledge/*.md`，运营维护、长期为真）检索出来的片段。
**检索覆盖不到当前场景是常态，不是错误**——下面写「没有检索到相关知识」，不代表这类
情况没有已知规律，只代表这次没搜到，不能因为这行字就断定「这里没有先例」。

反过来，检索到的内容本身可信，但它说的是**跨地图/跨局普遍成立的规律**（比如「门要怎么
碰」「菜单里哪个键是确认」），不是这一帧此刻发生了什么——**不能拿它替代「已知事实」里的
证据，也不能用它断言这一帧具体发生了什么**，只能用来指导「该怎么做」，不能用来判断
「现在是什么状态」。数据在下面「检索到的相关知识」一节。

## 相关记忆（怎么读）

每条记忆的形状是「当时看到 → 做了什么 → 之后变成」，前后两份是**同样的字段、同样的
顺序**，方便你逐行对照。**这是这一局自己走过的原始记录**，字段可以逐条核对。

**先对照，再下结论。** 有没有效果我们不替你判断——你要自己把「当时看到」和
「之后变成」逐个字段比一遍：

- 所有字段都一样 → **那个动作没有产生任何效果**，再做一次同样会没有效果。
  换一个做法，不要因为上一步的理由听起来有道理就重复它。
- 有字段变了 → 变的正是那个动作改变的东西。注意**只有一两个字段变**也是变了：
  战斗菜单里移动光标，只有 `光标` 那一行会变，位置和四邻不会变。

记忆里的「因为」是**当时的自己**给的说法，不是已经验证过的结论。它说了什么，
和那一下有没有效果，是两件独立的事——以「之后变成」为准。数据在下面「相关记忆」一节。

## 跨局摘要记忆（怎么读）

这是**之前几次尝试**（不是这一局）事后蒸馏出来的经验摘要——跟「相关记忆」不是
一回事：那是这一局自己走过的原始记录，字段可以逐条核对；这里是别的局自己总结的一段话，
**可能带着那一局自己的偏差或错误结论，没法逐字段核对，可信度比「相关记忆」低**。
两边冲突时，以这一局自己实际看到的（已知事实/相关记忆）为准，这里只作参考，
不能当成结论直接采信。数据在下面「跨局摘要记忆」一节。
