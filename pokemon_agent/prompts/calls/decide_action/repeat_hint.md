## 怎么用按键链
一步交出的是一条**按键链**（`sequence`），不是一个键。链里每一段写 `{"action": 键, "times": N}`，N 最多 8。

**每交出一条链只花一次决策调用 + 一次视觉感知，链里的方向键本身不要钱。** 把一条直线拆成五次决策，就是把决策和感知的成本乘以五，而中间那几帧你也读不到新东西——只有坐标、朝向、地标，场景和对话都读不到。

### 三条硬规则
- 链**长度为 1**时：任意可用按键，`times` 1-8；例如单独按 `a` 时使用一个元素的 sequence。
- 链**长度大于 1**时：前面每一段只能是方向键 `up`、`down`、`left` 或 `right`（可以在一条链里转弯），**最后一段可以是 `a`**——例如 `[{"action": "up", "times": 2}, {"action": "a", "times": 1}]`：走过去，再按一下。
- `a` 在一条链里**最多出现一次，且只能在末尾**：中间帧看不到，`a` 放在中间等于把它打开的对话/菜单整个丢掉；放在末尾时那一帧正好会被观察到。
- `a` 的 `times` 永远是 1，写大了也会被改成 1。

### 怎么规划
先在 `walk_map` 上把路径数出来，再看开头能一次走掉多少：

- 路径 `down, down, right, right, right`：可以一步交完 `[{"action": "down", "times": 2}, {"action": "right", "times": 3}]`。
- 路径 `up, up, down`：可以一步交完 `[{"action": "up", "times": 2}, {"action": "down", "times": 1}]`。
- 路径 `right, right, up`：可以一步交完 `[{"action": "right", "times": 2}, {"action": "up", "times": 1}]`。
- **原路折回也是一条合法的链**：`[{"action": "up", "times": 4}, {"action": "down", "times": 4}]`
  在同一段路上来回走了 8 格，只花一次感知。要在一小片地方多踩几格
  （比如在草丛里等遭遇），这比往一个方向按到底好——按到底会走出这片地形。

`times` 直接从 `walk_map` 上数：沿那个方向连续有几个 `.`（或 `G`），数到 `#`、`D`、`S`、`N` 或要转弯的那格为止。**数的时候忽略每行末尾的 `(x=..)` 括号**——那是全局坐标标注，不是格子。

### 什么时候别用长链
连按和多段链期间**看不到中间画面**，所以只在确信中途不会有事发生时才拉长：路上要穿过 `G`（会遇野生宝可梦），或者你预期会触发对话、换图，就把这一步缩短，先走到能看清的地方。

**撞墙是唯一不必为此担心的错**：它只废掉那个方向上剩下的连按，你后面另写的几段照按（原路折回本来就要撞一次墙）。真正该缩短的是「走几步能到」你数不出来的那一段。
