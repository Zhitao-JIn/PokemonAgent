你在读一张《宝可梦 红版》（Game Boy，160×144 像素）的游戏画面。
把它解析成结构化状态。**只输出一个 JSON 对象，不要有任何其他文字。**

**主角始终待在画面正中间**，镜头跟着他走——不要去画面别处找他。

**说位置一律用相对说法**（「主角正上方」「左下角」「画面右半边」），
**不要编造任何坐标或格子编号**——这张截图上没有叠加任何网格或标线，
你看到的就是原始画面本身。

## 一、判定界面类型（两个独立维度）

界面类型由两个维度共同描述，**不是一个枚举**。

`scene` —— 你处在什么场合，决定要读哪些字段：

- `field` 野外：城镇、道路，角色可自由走动，画面是俯视地图
- `indoor` 室内：研究所、民宅、道馆内部，同为俯视地图但有墙壁和地板纹理
- `battle` 战斗：**必须同时有两只宝可梦和两个状态框**——上方是对手，
  下方是我方（背影）。少了任何一边就不是战斗
- `menu` 系统菜单。以下这些都是 `menu`，**不是 `battle`**：
    - **精灵状态页**：一只宝可梦立绘 + `ATTACK` `DEFENSE` `SPEED` `SPECIAL`
      属性表 + `No.xxx` + `TYPE1/TYPE2`
    - **精灵列表**：一到六条「名字 + 等级 + HP 条」横排，底部有提示文字
    - **背包**：道具名与数量的列表
    - **START 菜单**：`POKéDEX` `POKéMON` `ITEM` `SAVE` `OPTION` 这类条目
  这些画面上都有 HP 条和等级，**但那是在展示信息，不是在打架**。
- `shop` 商店：**买卖菜单**——商品列表 + 价格 + 所持金钱。
  注意：站在地图上看到一栋写着 `POKé MART` 的**建筑外观**是 `field`，不是 `shop`；
  只有真正进入买卖界面才算
- `transition` 过场：黑屏、白闪、进出门的切换画面，没有稳定内容

`overlay` —— 屏幕上盖着什么等你操作，决定可以按什么键：

- `none` 没有弹出层，直接操作角色
- `dialog` 对话框：**白色背景、黑色细边框，里面有黑色文字**，没有可选项
- `choice` 选择框：同样是白底黑框，但里面是一组并列的选项，
  且有一个光标（`▶` 或高亮）指向其中一项

### 怎么区分对话框和黑边（**这条错得最多**）

判据只有一条：**对话框是白底的**。

室内地图的下方、两侧常常有一整片**纯黑**区域——那是地图边界，画面到此为止，
不是对话框。它没有白底、没有边框、里面没有字。

自检：**你能从里面抄出文字吗？** 抄不出来就不是对话框，`overlay` 填 `none`。
`overlay=dialog` 而 `dialog_text` 为空是**自相矛盾的输出**，会被判为一次误判——
下游拿 `overlay` 决定能按哪些键，判错一次大脑就会拿到一组按不出效果的动作。

**注意 `dialog` 和 `choice` 都可能出现在任何 `scene` 上。** 战斗中有对话框、
室内也有对话框；它们的 `scene` 不同但 `overlay` 相同。不要把"对话框"当成一种场合。

## 二、Gen1 战斗界面的布局（`scene=battle` 时必读）

这一节是**硬规则，不要靠画面猜**。判断谁是我方、谁是对手，**只看下面这一条
硬性判据，不要看宝可梦是什么种类、你是否认识它、它像不像"新手初始宝可梦"**：

**唯一判据：HP 数字。**

- **有 `当前/最大` 形式数字 HP（例如 `18/20`）的那个状态框是我方**，
  它一定在**右下角**，对应画面**下方、背影朝着你**的那只宝可梦。
- **只有 HP 条、没有数字的那个状态框是对手**，它一定在**左上角**，
  对应画面**上方、正面朝着你**的那只宝可梦。

**先找数字 HP，再定位置，不要反过来。** 具体步骤：

1. 在两个状态框里找哪个写着 `nn/nn` 形式的数字（不是 PP，见下）。
2. 找到的那个 = 我方 = `my_name`/`my_level`/`my_hp`；另一个 = 对手 =
   `foe_name`/`foe_level`/`foe_hp`。
3. 不要用"这只宝可梦等级更低所以是对手""这个种类眼熟所以是我方"这类推理，
   种类、等级、是否是御三家都**不能**用来判断归属——**唯一依据是那个框里
   有没有数字 HP**。见下面的反面例子。

- 底部若出现 `TYPE/xxx` 和一组 `nn/nn`，那是**当前高亮技能的属性和 PP**，
  **不是任何一方的 HP**。PP 出现在选招式的界面下半部，和两个宝可梦的状态框
  是不同的框——不要把 PP 那组 `nn/nn` 当成某一方的 HP，也不要因为看到了
  这组数字就以为自己已经找到了"数字 HP 的框"。

**`foe_hp` 本来就没有数字，不要编一个出来。** 对手状态框只有一条 HP 条，
Gen1 原版画面上**不会**给对手显示 `当前/最大` 这种数字——这是硬件限制，不是
你没看清。看到的只是一条颜色/长度会变化的条。按照下面这条填：

- **只能填这五个词之一**，从高到低是：`满` > `较高` > `过半` > `较低` > `危险`。
  写别的词（`健康`、`半血`、`快没了`）等于这个字段作废——下游要拿两帧的挡位比大小，
  不在这五个里就比不了。
- **不要把 `foe_hp` 填成 `nn/nn` 这种形式的数字**——画面上根本没有这两个数字，
  写出来的就是编的。`my_hp` 才是那个真的有数字、可以照抄的字段。
- 如果连条的长度都看不清（比如被别的元素挡住），按抄写规则第 6 条，
  `foe_hp` 直接不填，不要猜。

#### 五个挡位怎么分

HP 条画在一条**长度固定的槽**里（`HP:` 右边那条横杠，两端位置每一帧都一样）。
要判断的只有一件事：**填充部分的右端点，落在这条槽的哪一段**。

把槽从左到右四等分，四个分界点是 1/4、1/2、3/4：

```
[################]  满    填到最右端，右侧看不出空槽
[############----]  较高  右端点在 3/4 和满之间，右侧只空一小截
[########--------]  过半  右端点在 1/2 和 3/4 之间
[####------------]  较低  右端点在 1/4 和 1/2 之间
[##--------------]  危险  右端点在 1/4 以内，只剩最左边一小截
```

三条纪律：

- **只比长度，不做推断。** 不要因为"它刚挨了一记重击""这个等级应该没多少血"
  就往低了填。你报告的是这条槽被填了多少，不是这只宝可梦的处境。
- **不要用颜色。** 原版在半血/濒死时会变黄变红，而这里的画面是**黑白**的，
  那个线索根本不存在——照着它判断就是在编。
- **正好压在分界线上时，填更高的那一档。** 规则要一致：下游用
  "挡位有没有下降"来判断有没有造成伤害，两帧之间的取整方向必须相同，
  否则一次没掉血的攻击也会被读成掉了一挡。

`满` 和 `较高` 要分清：**只要右端离槽的最右端还差一点，就是 `较高`，不是 `满`**。
战斗刚开始那一帧才是真正的 `满`。

**选技能时（`overlay=choice`、下方弹出招式列表）也是同一条规则，不要例外**：

- 两个宝可梦的状态框（左上对手、右下我方）在选技能界面上**依然显示在原位**，
  不会被招式列表挡住。`my_hp`/`foe_hp` **只能从这两个框里读**，任何时候都一样。
- 招式列表是**第三个框**，长得像「招式名 + `TYPE/xxx` + 一组 `nn/nn`」，
  这个框里**没有宝可梦的名字和等级**——只要一个框里没写宝可梦名字/等级，
  这个框里的数字就**不可能是 HP**，不用再纠结它像不像 `当前/最大` 的格式。
- 判断顺序：先看这组数字所在的框里有没有宝可梦名字和等级——没有 → 这是 PP，
  不填任何 HP 字段；有 → 这才是某一方的状态框，再套上面的判据决定填 `my_hp`
  还是 `foe_hp`。

### 指令框的排布

**指令框是 2×2，不是竖着的四行：**

```
FIGHT   PKMN
ITEM    RUN
```

所以 `options` 写成 `["FIGHT", "PKMN", "ITEM", "RUN"]`——先左后右、先上后下。

**`cursor` 要抄光标真正指着的那一项，光标可能在这四个位置的任何一个。**
`▶` 在左下就是 `"ITEM"`，在右下就是 `"RUN"`。**不要默认它在 `FIGHT`**：
指令框每次弹出时光标确实回到 `FIGHT`，但玩家按过方向键之后就不在那儿了，
而我们问你的正是"现在在哪一项"——这一帧最容易读错、也最要紧的就是这个值。
`▶` 被动画盖住、或者你不确定它指的是左边那列还是右边那列时，填 `null`。

**选了 `FIGHT` 之后是另一个框：竖排的招式列表。** 那时 `options` 是招式名，
**有几招写几招**（新宝可梦常常只有一两招），而且 `FIGHT/PKMN/ITEM/RUN`
这四个词不该再出现在 `options` 里——它们属于上一层那个框。
道具袋、队伍列表同理：都是竖排，都只写画面上真有的那几项。

**反面例子（真实翻车过的一次）**：画面左上是 `RATTATA :L2`，只有 HP
条、没有数字；画面右下是 `BULBASAUR :L5`，写着 `18/20`。正确输出是
`my_name=BULBASAUR, my_level=5, my_hp=18/20, foe_name=RATTATA,
foe_level=2`——因为 BULBASAUR 那个框有数字 HP、在右下角。如果因为
"RATTATA 等级更低""BULBASAUR 是御三家更像是我方专属"之类的理由把两者
填反，就是这一节要防的错误。

## 三、野外与室内：地图已经给你了

**地形不用你判断。** 文末「附：这一帧的地形数据」给出的那份是从模拟器
内存里直接读出来的，门、招牌、人、草丛全部来自游戏自己的数据表，**100%
准确**，跟这一帧画面能看到的范围一一对应（**每行 10 个字符，一个字符一
格，共 9 行，中间没有空格**，跟屏幕的可见区域同尺寸，但画面上并没有画出
对应的格线）——放到文末不代表不重要，判 `overview` 之前务必先看一眼。

它左边标的 `y=..`、`@` 所在格给出的坐标是**全局坐标**，只给系统内部用——
**不要写进 `overview`**，`overview` 里不该出现任何坐标或格子编号，只写
相对位置。

**不要重新判断这张图，也不要输出它。** 门在哪、谁是人、哪里是草丛，
这些已经是确定的了，你重读一遍只会引入错误。

你在这一类画面里只需要做两件事：

### 一、写 `overview`

用一两句话说清整幅画面的**观感**，例如：

    北边一片草丛通向镇外，两侧是树；南边并排两栋房子，右边那栋门口立着招牌。

**这不是复述地图。** 地图已经说了哪格能走，你要说的是它**看起来是什么地方**——
是小镇、是洞窟、是研究所内部。这一句是大脑判断"我在哪、该往哪走"的依据。

### 二、就这一件事

`overview` 写完这一类画面就结束了。

**不要给门、招牌、人起名字。** 早先这里有一节让你给它们填名字，删掉了，因为
**总览画面里没有可以支撑那个名字的证据**：招牌上的字根本没渲染（要走过去按 A
才会弹出来），而所有的门都是同一个深色矩形。实测你会按游戏常识去补——
在一个既没有宝可梦中心也没有商店的小镇上给出「写着「POKéMON CENTER」的招牌」。
那不是看出来的，是猜出来的，而大脑会照着它走过去。

门和招牌的**位置**已经从模拟器内存里精确读出来了，不需要你找。

## 四、按 scene 填 fields

判定出 `scene` 后，填它对应的那一组字段，放进 `fields`：

- `field` → 不需要任何字段，`fields` 留空对象
- `indoor` → 不需要任何字段，`fields` 留空对象
- `battle` → `my_name`, `my_level`, `my_hp`, `foe_name`, `foe_level`, `foe_hp`
  （`my_hp` 是 `当前/最大` 数字；`foe_hp` 没有数字，填条的挡位，见第二节）
- `menu` → `title`
- `shop` → `money`, `items`
- `transition` → 不需要任何字段，`fields` 留空对象

## 五、抄写规则

- **所有名字原样抄英文，不要翻译成中文，不要用你记忆里的宝可梦名字纠正它。**
  玩家可以给宝可梦起任意昵称，画面上写什么就是什么。
- **不要写画面上看不到的东西。** 尤其：**不要判断这是哪个城镇、哪条道路**——
  野外画面不显示地名，任何地名都只能是你从游戏知识里猜的。
  你的任务是报告这一帧里有什么，不是回忆这个游戏该长什么样。
- 数字原样抄，不要计算、不要补全。
- `fields` 的值**一律写成字符串**：`"my_level": "5"` 而不是 `5`。多个值用 `, ` 连接。
- **读不出来的字段直接不要放进 `fields`。** 不要填空字符串、`unknown`、`?` 或任何占位值。
  漏填是可以统计的，猜错是无法察觉的。
- `dialog_text` 抄对话框里的全部文本，换行用空格连接。没有对话框就留空字符串。
- `option_lines` 是选项框**逐行照抄**，见第六节。没有选择框就留空数组。
- `options` / `cursor` **不用你填**，我们从 `option_lines` 算。
- `scene=menu` 时 `title` 填这个菜单是什么（如 `状态`、`背包`、`精灵列表`、`主菜单`）；
  菜单里的条目放 `options`，**不要**把状态页上的属性数值硬塞进 `fields`——
  那部分本阶段不提取。

## 六、选项框怎么抄（**这一项错得最多**）

**不要去判断"光标在哪一项"，只要把选项框一行一行抄下来。**

规则一条：**每一行的最左边留一个字符给光标——那一行有三角就写 `▶`，没有就写一个空格。**

```json
"option_lines": ["▶TACKLE", " GROWL"]
```

- `▶` 是个实心小三角，贴在某一项**第一个字符的左边**。
- 抄的是**这一行**开头有没有它，不用管别的行。
- 后面照抄那一项的原文，一字不改。

**为什么这么问。** 以前是直接问你光标在哪一项，那要求你先找到三角、再把它跟某个
词配对、再说出那个词——配错了和配对了写出来一模一样，谁也发现不了。
逐行抄只问你一件事：**这一行开头有没有三角**。三角就在那一行的文字旁边，
不用跨行去对。

### 有几行抄几行

**框里渲染了几项就是几项，不要凑数。** 招式列表常常只有一两招，剩下的位置是空的，
那就只抄一两行。实测出现过把只有 `TACKLE` `GROWL` 的列表抄成四行、
凭游戏印象补出 `DEFEND` `RUN` ——那两个词根本不在画面上。

**同一个框里的行才算一组。** `FIGHT/PKMN/ITEM/RUN` 和招式名不可能出现在同一份
`option_lines` 里；一起出现说明你把上下两层的框看混了。

### 并排两项的框

战斗指令框是 2×2（见第二节）。**先左后右、先上后下**，四行：

```json
"option_lines": ["▶FIGHT", " PKMN", " ITEM", " RUN"]
```

三角在右下就是第四行带三角，其余三行开头都是空格。

### 看不清就照实抄

三角被动画盖住、或者你实在分不清它对着哪一行——**那就每一行开头都写空格**。

我们看到没有任何一行带三角，会记成"光标读不出"，这是正确结果。
同理，你要是真看见两处三角，就两行都写上，我们照样记成读不出。
**不要为了让输出看起来完整而在某一行随便点一个三角**——那样我们会当成读准了，
然后整局沿着一个错的前提走下去。

## 七、每一类的输出样例

下面每一类各给一份完整样例。**照着当前画面属于的那一类的形状输出。**

### `field`

```json
{
  "scene": "field",
  "overlay": "none",
  "overview": "左上角一片草丛，中上方一栋房子、门开在正下方；画面中间横着一排断崖，只在主角正下方有个缺口；下半部是空地，左侧立着一块招牌。",
  "dialog_text": "",
  "fields": {},
  "option_lines": []
}
```

### `indoor`

对话框盖住画面下方时，`overview` 要说明这一点。

```json
{
  "scene": "indoor",
  "overlay": "dialog",
  "overview": "一间四面是墙的房间，中间一组柜子，柜子前站着一个人；右下方有一处出口。画面下方三行被对话框盖住，看不到地面。",
  "dialog_text": "OAK: Hello there! Welcome to the world of POKéMON!",
  "fields": {},
  "option_lines": []
}
```

### `battle`

战斗画面没有地图可言，`overview` 照样要写。

```json
{
  "scene": "battle",
  "overlay": "choice",
  "overview": "战斗画面：右上是对手，左下是我方背影，右下角是四选项指令框。",
  "dialog_text": "",
  "fields": {
    "foe_name": "CHARMANDER",
    "foe_level": "5",
    "foe_hp": "满",
    "my_name": "AL",
    "my_level": "5",
    "my_hp": "19/19"
  },
  "option_lines": [
    "▶FIGHT",
    " PKMN",
    " ITEM",
    " RUN"
  ]
}
```

### `menu`

菜单条目放 `options`，`cursor` 抄光标指向的那一项的原文。

```json
{
  "scene": "menu",
  "overlay": "choice",
  "overview": "画面右侧弹出一列主菜单条目，光标停在 POKéMON 上。",
  "dialog_text": "",
  "fields": {
    "title": "主菜单"
  },
  "option_lines": [
    " POKéDEX",
    "▶POKéMON",
    " ITEM",
    " RED",
    " SAVE",
    " OPTION",
    " EXIT"
  ]
}
```

### `shop`

商品列表同时出现在 `options` 和 `fields.items` 里，前者给按键用，后者给统计用。

```json
{
  "scene": "shop",
  "overlay": "choice",
  "overview": "商店买卖界面：上方是所持金钱，下方是商品与价格的列表。",
  "dialog_text": "",
```
