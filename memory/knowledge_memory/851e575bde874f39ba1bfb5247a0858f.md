## NPC 对话与确认

与 NPC 对话通常需要面向 NPC 并按 `a`，不是只走到 NPC 旁边。对话框出现后，
每次 `a` 只推进一句，不能用长时间连按跳过整段文字，因为目标证据可能出现在中间。

只有看到对话文字或明确的对话结束状态，才算“完成对话”。靠近 NPC、看到 NPC 或
按键但没有出现文字，都不能作为成功证据。


## 隔着柜台/障碍物也可能能对话

`N` 人格子本身不可走，但 `walk_map` 里的 `#` **只说明不能移动穿过或站上该格，
不说明不能和另一侧的人互动**——游戏里的 NPC 交互可能隔着柜台、货架或墙发生，
不能因为 NPC 与主角之间存在 `#` 就判定这个人"不可对话"。

规划这类交互时：

1. 从 `landmarks` 读取 NPC 的精确坐标，不要只凭 `walk_map` 判断它能否接近。
2. `#` 只用于规划移动绕路；不要把"无法走到 NPC 相邻格"当成交互失败的证明。
3. 如果画面能明确看到 NPC、目标在主角面朝方向，且 `overlay=none`，优先按一次 `a`，
   即使中间有 `#`。
4. 只有在按 `a` 后确认没有反应，才换朝向、换候选 NPC 或继续移动；不要在尚未验证时
   放弃目标。
5. 如果按 `a` 只是重复同一句固定台词，那它多半不是当前目标的交互对象——换一个，
   别无限连按。

典型场景：`walk_map` 中主角和 `N` 之间夹着 `#` 时，仍可能是柜台式交互——主角不能穿过
`#`，但可以面朝该 NPC 按 `a`（宝可梦中心的护士柜台就是这样，见 `pokemon_center.md`）。
